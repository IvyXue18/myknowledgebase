## 一、核心提炼

### 一句话

**这半年真正的分水岭不在模型和功能，而在"填 gap"——模型能力与真实业务之间、agent 与普通人之间、技术速度与制度速度之间，都横着一道落差；谁能把落差填平（服务 / FDE / 一个可复制的场景 / 一套自带的 onboarding），谁才算真的把 AI 交付出去了。**

### 十条主干

**1. 服务裹着能力，而不是能力裹着服务。**
同一个 agent 放在不同人手里，效果差异大到不像同一个产品。买了账号、买了 token ≠ 拿到结果——它跟买飞书、买企业微信不一样，不是"软件到了大家直接就用"。中间那道落差，只能由服务去填。做产品的公司得重新想这件事：不是去建个培训团队，而是要有"交付产品之后还有一段 gap"的意识。

**2. 填平落差有三条路，本质是同一件事。**
① 等 5% 的超级用户自己跑出来，做出优化后其他人跟着用；② 培训，不可能人人培训，但有总比没有好，至少能把那 5% 捞出来；③ FDE——培训来不及、自己人还没长出来时，产品带着服务直接进场，现场摸爬滚打出一条最佳实践。

**3. 国内很多"FDE"是换汤不换药的外包。**
真假的分界线：团队走了以后，落差还在不在。真 FDE 的成功指标是**把自己抽离掉**——不是陪伴越久越好，而是你撤了之后客户还能带着你的脑子运转。零一万物对标 Palantir 的打法是「二 + 三」：先带着产品做内部培训（转化率约 75%），再派 FDE 入驻，FDE 有股权、不背销售指标，毛利高、复购高。

**4. 教育用户靠的是一个能被复制的场景，不是功能列表。**
抢外卖券、千问点奶茶、整理桌面、Three.js 小 demo——本质都是"最佳实践的封装"，像一句咒语，所有人念同一句就能拿到结果。国内大厂的问题是：自己也不知道产品怎么用，只会砸钱推广、只会比谁功能多，指望推广的人替它把生态和内容做起来。

**5. 齿轮速度差：越传统的行业越容易出效果。**
技术两三个月一变，组织变得慢，制度、利益分配、商业结构更慢。服务就是在填这个速度差。所以 Palantir 也好、零一万物也好，都去挑传统行业（比如养鸡）——链条短、反馈快、见效快、甲方愿意为价值付费；反倒是内容行业，你进去可能发现自己用得还不如人家好。

**6. AI 改不动的那一段：渠道、支付、财务、盖章、入库。**
"OPC 的一天"——跑财务一天、开票一天、签合同一天；八份合同 120 张纸盖 80 个章，没有一次是对的。跟大厂合作走入库流程走了一年，等入完库项目已经不存在了。**coding 之所以快，恰恰因为它不依赖这些。** 这也是为什么 Stripe、Airwallex 这类把后链路自动化做到极致的 infra 显得那么可怕——以及为什么"服务一人公司的服务公司"反而是个真需求。

**7. Skill 的商业化是个结构性悖论。**
to C 收不到钱：用 skill 本身就在烧 token，你还要再收一次；而且 skill 不保密，下下来就是开源的。橘子的解法是绕开 to C——跟 agent 厂商做授权 + 赞助开源：顶尖 skill 让用户拿到好结果，用户会把这个结果归功于 agent 产品本身，你是在为它赋能。但 skill 本身也很难用，一步比一步难；每个人也不需要那么多 skill。**skill 更像模板，真进自己的工作流一定得自己定制——这就是"个人的 FDE 化"。**

**8. Agent + X 还是 X + Agent，是这一代最大的分岔。**
有基本盘的公司必然选 X + Agent（Office、微信小 V），在原有产品里插一个对话框；但生插是别扭的——不原生、跟老 UI 割裂、旧的免费商业模式 cover 不住 token 成本、旧组织和旧基建也接不住。Agent + X 后劲更足：极致形态就是手机变成一块屏、一个对话界面。
**但只有 chat 是不行的**——人的记忆力撑不住，人必须看到目录/界面才想得起来自己要干嘛。所以每个软件接下来都会做一个 dashboard，把 chat 里散落的待办和未完成工作全部呈现出来。那是一套**动态的、随时变化的新 UI**。

**9. 上下文是一辆要维护的车，不是一套升值的房。**
垒得越多，它越会把你拉回自己过去的平均值——这就是 AI 的信息茧房。做法是：进入时先清洗加工（说清这次的背景、话题、边界），做好索引，别让它上来读所有东西，按项目做上下文分区，一层层抽象（项目信息是客观的，认知是主观的，分开放）。同时另一半人是反过来的：**根本没有上下文，也不知道上下文在哪儿——"你问他上下文在哪儿？微信啊。"**

**10. 被整个效率圈忽略的另一半：AI 内容消费。**
"我们这波人关注 agent、效率、生产，但非常多的 C 端用户根本不需要用 AI 工作。"AI 在内容消费上的渗透比在生产力上快得多——AI 短剧渗透已超 8 亿，短剧正在"网文化"：能日更，又有长篇剧情和复杂架构。钩子是生理级有效的（明知有人在引导你，还是一集接一集）。讲故事的门槛降到零之后，"有资格讲故事、能讲好故事的人会越来越多"；而好故事跟时长、跟是不是 AI 做的，都没关系。

### 几句可以直接引用的话

- 「服务裹着能力，而不是能力裹着服务。」
- 「衡量 FDE 成不成功的唯一指标，不是陪伴用户越久越好，而是你抽离之后，客户还能带着你的脑子运转。」
- 「上下文是一辆要维护的车，不是一套升值的房。」
- 「软件已死。SaaS 本身就不是软件，SaaS 是服务；AI 也一样，你用 token 买的是服务。」
- 「产品就是自己带一套 FDE。」
- 「你不能指望拿钱做推广的人，会帮你把生态、服务、内容做起来。」
- 「越传统的行业，越容易砍出效果，越容易让甲方为你的价值付费。」
- 「你问他上下文在哪儿？微信啊。这个 gap 很大。」
- 「第一层觉察是应该形成自己的闭环，不要抄别人的；第二层是要意识到自己正在一个环里，别被困住。」
- 「如果 harness 和模型是解耦的，模型厂商就会陷入红皇后效应——你只有拼命奔跑，才能停在原地。」

## 二、可以拆出去做的选题

> 按「能不能独立成篇 + 有没有具体证据/案例」排的，前 5 个是我认为最值得先做的。

### 选题 1 ｜服务裹着能力，而不是能力裹着服务
- **论点**：AI 产品交付的终点不是账号和 token，是结果。中间那道落差只能靠服务填。
- **素材**：同一个 agent 在不同人手里差异极大；「它跟你买一个飞书、买一个企业微信不一样」；三条填 gap 的路。
- **形式**：公众号长文 / 视频口播。这是整场对谈的主干，适合做「主文」。

### 选题 2 ｜真 FDE 和假 FDE：判断标准只有一条
- **论点**：国内大量所谓 FDE 是"带团队来开发，开完就走"，人走了落差还在——那不是 FDE，是外包。真 FDE 的 KPI 是把自己抽离掉。
- **素材**：杨攀在返校日的判断；零一万物对标 Palantir 的「培训（75% 转化）→ FDE 入驻（有股权、不背销售）→ 抽离」；毛利高、复购多。
- **形式**：公众号深度文。这是全场信息密度最高、最"可被转发"的一段。

### 选题 3 ｜一个抢外卖券，胜过一百条功能更新
- **论点**：教育用户的最小单位是"一个能被原样复制的场景"，不是功能列表。它是最佳实践的封装，像一句所有人都会念的咒语。
- **素材**：抢外卖券、千问点奶茶（接了支付能力）、整理桌面、Kimi 想让大家看后端而 KOL 只能演前端、Three.js demo 满天飞、模型发布会上的 3D 演示"看腻了且不代表能力"。
- **形式**：短视频/图文都很合适，案例自带传播性。可以直接做成「AI 产品冷启动的场景公式」。

### 选题 4 ｜OPC 的一天：AI 改不动的那一段
- **论点**：AI 提效止步于制度。渠道、支付、开票、资质、法人签字、入库流程——这些是速度差最大的地方，也正因如此，coding 才跑得最快。
- **素材**：八份合同 120 张纸盖 80 个章没一次对；跑财务一天/开票一天/签合同一天；某大厂入库走了一年，入完项目没了；换主体要重来一遍；Stripe 和 Airwallex 把后链路做绝。
- **形式**：这是全场最有画面感、最"人味"的一段，做视频或情绪向长文都成立。延伸出一个真问题：**企业的 SOP / 入库流程能不能也开放一个标准 client 给 agent 对接？**

### 选题 5 ｜上下文是一辆要维护的车，不是一套升值的房
- **论点**：上下文不是越多越好。堆到一定量之后，它会把你拉回过去的平均值——AI 的信息茧房。
- **素材**：明确在 prompt 里说了新想法，它还是引用旧结论；进入时先清洗加工、说清背景与边界；做索引、按项目分区、把"客观项目信息"和"主观认知"分层抽象；两层觉察（形成自己的闭环 / 意识到自己在环里）；有人和 agent 互吹说自己解决了幻觉问题。
- **形式**：方法论文章，实操性最强，最适合做成可复用的 SOP/清单。

### 选题 6 ｜Agent + X 还是 X + Agent
- **论点**：两条路都能到山顶，但 X + Agent 是"生插"——不原生、跟老 UI 割裂、旧的免费模式 cover 不住 token 成本。Agent + X 后劲更足。
- **素材**：微信小 V 的别扭感；手机变成一块屏的思想实验；App Store 生态的没落。
- **形式**：观点文 / 辩论式视频。可与选题 7 合成一篇。

### 选题 7 ｜只有 chat 是不行的：人永远需要一个目录
- **论点**：对话界面能解决一切问题，但人的记忆力撑不住——你得看到那个仓库，才想得起来自己要干嘛。所以下一步是动态 dashboard。
- **素材**：「我订了票，明天就忘了，我需要看到那个界面才能想起来」；上千条笔记同理；「把 chat 中的待办、遗留未完成的工作全部在 dashboard 中呈现」。
- **形式**：产品设计向文章，配一张"chat + 动态 dashboard"的结构图效果最好。

### 选题 8 ｜A2A：人与人之外的第二张网
- **论点**：H→A→A→H 这条新链路成不成立，卡在两个假设上：agent 足够懂你（正在变好）、agent 之间能互相发现（网还没成型）。
- **素材**：Cola 试过让两个 agent 对聊，用户学不会、太抽象；群聊这个心智本身就是学来的，国外并不流行；新建网络会丢上下文、极难；「条件具备时，网会自己冒出来」；A2A 社交找 soulmate 的两个前提；「你们两个是不是合适，你自己都不知道，AI 凭什么知道」。
- **形式**：前瞻观点文，争议性强，适合做暴论型内容。

### 选题 9 ｜别人的 AI 味 vs 自己的 AI 味
- **论点**：人对自己 AI 的输出接受度高，对别人 AI 的输出接受度极低——所以中间会长出一层"A 的转述/翻译"。
- **素材**：「别人的 AI 写的是 AI slop，自己的还行，特别奇怪」；模型加水印引发反感的例子（示例里加水印前后文案完全不同，评论区"每个字都不对"）；「大家都觉得 Opus 4.6 好，因为它说人话」；「一句话里多一个字少一个字，传达的东西完全不一样」。
- **形式**：非常适合面向内容创作者的公众号选题，共鸣度高。

### 选题 10 ｜被效率圈忽略的另一半：AI 内容消费
- **论点**：我们讨论 agent 和生产力，另一半人根本不需要用 AI 工作。AI 在内容消费上的渗透远快于生产力。
- **素材**：AI 短剧渗透超 8 亿；「短剧正在网文化」——日更 + 长线剧情 + 复杂架构；「我脑子里分了两个我，我在观察我怎么被钩子一集一集钩下去」；Steam 上 AI 做的游戏增速很快；贾玲也疯狂刷短剧；「好故事跟时长没关系，跟人也没关系」；「两个圈子平时默认对方不存在」。
- **形式**：这是一条独立赛道的选题，也是最"反共识"的一段，值得单独做。

### 选题 11 ｜AI 看病：目前最有体感的落地
- **论点**：AI 在医疗侧的价值来自两项能力叠加——超长上下文阅读（医生只有 10 分钟）+ 强推理。
- **素材**：三个真实案例——慢性病十年看了十个医生没人听完他讲话，跟 agent 聊完推理出病因、拿药吃好了，胖了五到十斤；脑雾半年以为是甲减，结果是缺铁性贫血临界值；经期问题被常规开雌激素，实为胰岛素抵抗（空腹血糖永远正常，做胰岛素释放实验才发现高出五六倍）。
- **注意**：涉及医疗，写的时候必须明确"AI 给的是 option，最终要拿去找医生确认"——原对谈里当事人也是这么做的。
- **形式**：情绪 + 实用双高的选题，但要谨慎处理表述边界。

### 选题 12 ｜模型价格的两条线：SOTA 越来越贵，主流越来越便宜
- **论点**：价格曲线正在分化。SOTA 持平甚至上涨，主流模型指数级下降，中转站已经降不动了。
- **素材**：和英伟达朋友打赌 100 块钱、DeepSeek 降价赢了又涨价 12 倍还回来的故事；「基准上差五分十分，价格差 50 倍 100 倍，只看基准你觉得亏，真用起来你觉得值」；缓存 90% 和 95% 是两个成本节点，差两倍；DeepSeek 在自家 harness 缓存能到 100%；为降本压缓存过头会伤输出质量。
- **形式**：适合做数据/曲线图，也适合做「怎么选模型」的实操文。

### 备选（体量小，可以做补充或合并）
- **红皇后效应**：如果 harness 和模型解耦，用户零成本秒切，模型厂只有拼命奔跑才能停在原地——所以它们一定会走向 harness 与模型联合训练。
- **vibe coding 的人已经很多，但他们发不出去**：2.0 时代的基建高度封闭，"发内容可以，发产品不行"；很多人做完只有一个 127.0.0.1 的地址发给别人。小红书的小工具是个好口子。
- **GitHub 是 agent 协作的天然纽带**：git 协议完善、不需要上下文、所有 AI 都懂；issue/PR 已经成了 agent 之间的默认通信方式；但 AI 时代的提交量让人审不过来，托管平台需要新范式。
- **取景框 / role model**：给 AI 一个"我想成为什么样的人"的长期方向，它才能关联起来；没有方向，它帮不上什么忙——很多人甚至不会提问。
- **语音输入法和默认翻译**，是过去一年最切身的两个改变：语音输入是"跟自己对话"的心智，打字是"自斟自酌"的心智，两条完全不同的路。

## 三、对谈全文（整理版）

### 00 片头金句

> 模型能力和你的业务中间有一个 gap，那个 gap 的填充就是现在所说的 FDE。这句话再提炼一下：**服务裹着能力，而不是能力裹着服务。** 很多做产品的公司可能得重新思考一下这件事——不是说我要做一个培训团队天天去培训我的客户，而是你要有这个意识：我不是把产品直接交付出去就完了，中间还有一个 gap 需要去做。

> 不可能说人人在用 agent 的时候都达到同一个水平。你只能尽可能地让那 5% 用得最好的人，给那些人提供自动化。

> 抢外卖券是一个非常大的需求。他们用这个需求——每天自动帮你抢外卖券——通过这种方式教育用户怎么用 agent。找到一个场景，然后让大家去复制这个场景。

> SaaS 本身并不是一个软件，SaaS 是一个服务。AI 也一样，你用 token 买的是服务，而不是软件。软件已经死了，其实。

> 但我发现一个问题：他拥有我的上下文太多之后，我现在有一些新的思考，即使明确在 prompt 里告诉他怎么做，他还是会把我拉回到以前的平均值。**我现在越来越感觉，上下文是一辆要维护的车，不是一套升值的房。**

### 01 我们之前比的是产品功能，但差异其实不在功能上

**Q：大家这半年有什么新的认知变化？**

我想说一个。我们之前在比的是产品能力——WorkBuddy（音）和别的 agent 有什么功能差异？你们有什么区别？大家会这么去问。

但最近我的感受是：**差异点其实不在功能上。** 也就是说，不是产品改变了企业和最终交付的结果，而是服务。

一个产品给到一家公司，大家买了账号、买了 token，它并不会真的就带来很好的结果。因为这跟你买一个飞书、买一个企业微信不一样——它不是一个软件回来了，大家聊天直接就用了。而是这个东西的使用是因人而异的。同样一款产品，不同的人来用的时候，那个区分度非常大。

那这里怎么办？就会有一个落差，这个落差就是服务去填进去的。模型能力和你的业务中间有一个 gap，那个 gap 的填充就是现在所说的 FDE。

这句话再提炼一下：**服务裹着能力，而不是能力裹着服务。**

因为我们都知道，同样的 agent 能力放在不同人手中会产生很大的差异。那这个 gap 你怎么去填补？你不可能现在再从孩子的教育开始，来不及嘛——我们讨论的是现有企业里边的员工。所以从这个逻辑上说，我最近的一个感受是：很多做产品的公司可能得重新思考这件事。不是说我要做一个培训团队去天天培训我的客户，而是你要有这个意识——**我不是把产品直接交付出去就完了，中间还有一个 gap 需要去做。**

刚刚跟橘子也聊到这个。我说现在本质上来说，大家都在卖服务。软件本身不值钱，不是说你软件做得好、功能多，实际上一定要落到一个服务上。

FDE 是一个比较 toB 的视角，其实 toC 也一样。这个 agent 给到普通 C 端用户，大家都不会用——除了豆包那样的基础功能之外的能力，大家都不会用，它都是有 gap 的。而 skill 就是一个填补 gap 的东西。但 skill 也有一定难度。

所以一个产品给大众去使用的时候，它要有一个内置的 onboarding，一套内置的逻辑，能够让用户用起来。我觉得这才是在 AI 模型上面去做所谓 AI 应用的本质——**要做成一个服务。**

### 02 国内大厂的问题：他们自己也不知道怎么用

我觉得国内这些大厂在做类似的事情的时候，是有包袱的，或者说是有一些认知问题的。他们老觉得，比如在运营或者教育用户上，我砸钱推广就可以了。

但你可以看到海外那些——做软件的人同时也在输出软件的使用方法、实践和服务，他在做的时候同时在教你用。

国内这个问题就比较严重：**他们自己也不知道怎么用**，这个很明显。然后在推广和宣传上，声音是割裂的——他还是在比大小，我的功能比你多，我上了一个新功能。但他可能自己也不知道这个功能对各行业的用户来说具体有什么作用。而对于他们自己内部的人来说，产品肯定是你自己最了解的，我觉得他们发声是不够的。

所以应该转变一个思路：**你不能指望拿钱做推广的人会去帮你把生态、服务或者内容做起来。** 首先你自己要把这个东西做起来，你得先给这些人素材，他们才能转变，才能把整个生态带起来。

（这里需要两种人相遇：一个是业务专家，一个是懂这个 agent 产品的人，双方得相遇。）

还有一个点是成本，成本还是高。比如 WorkBuddy（音），它通过一些任务——腾讯最擅长的那套逻辑和方法——让你能够以很低的成本，通过出卖自己一点点时间的方式，换取尝试的资格。而且它在免费这个层面上供应非常充足。

我觉得这也带来了一定的让用户成长的空间：他能从一个完全不懂的小白用户，变成一个"好像懂一点什么"的用户，而且不需要花很多钱。用户量大了以后，总会涌现出那么几个超级用户，你的生态就会变好。

**Q：听起来像是一个漏斗模型？先让大家把这个 agent 装上、用起来。**

对。但你真正用上了，还没有带来我们说的生产力结果的交付，那个流程的优化还没到那一步。再往深水区走的时候，服务还是得进去。

### 03 一个抢外卖券，胜过一百条功能更新

你知道我可巴里（音）他们有个很有效的策略，就是**抢外卖券**。

因为我们不在那个下沉市场里边，可能没感觉——但抢外卖券是一个非常大的需求。他们就用这个需求去做：你用我可巴里（音）可以每天自动帮你抢外卖券。就这样，他每天就能用起来。

有点像之前"千问点奶茶"那种感觉——不过千问点奶茶是因为它接入了支付能力。

我觉得他是通过这样的方式教育用户：你该怎么用这个东西。**得找到一个场景，然后让大家去复制这个场景。**

这个场景一旦落地了，它使用起来就相当于一个咒语、一个密码：就这么简单一句话，所有人都会说这一句话，然后就能拿到这个结果。

**它其实就是一种最佳实践的封装。** 只是在企业里具体落地的时候——做自媒体的这个群体、做出海营销的这类公司业务——不同的业务场景里细节特别多，那个最佳实践你需要去抽、去提。指望大家自己摸索、自己在那趟路，其实不一定那么高效。

因为你要真讲"AI 在我们企业里做了什么事情"，你讲完之后别人也听不懂，很难推广。所以现在大家的策略都是用一些一眼能 get 到的东西：比如外卖券，比如整理桌面。

你看 Kimi K3 出来之后，大家都去搞前端的案例。但你知道 Kimi 其实不太希望大家关注前端，Kimi 希望大家关注后端——可后端不可能拿来演示，KOL 也不可能去做那种东西，所以大家只能去做前端演示。因为它肉眼可见，肉眼可见才好传播。

所以 Three.js 的 demo 越做越多。你看 Opus 5 发布的时候不也全是那些 3D 的？那个都看腻了，因为没什么用——你平时谁会干这个、谁会用这个东西呢？而且那些东西其实也不能代表能力。（也不完全是：做出来是要成本、要人的，不是任何一个人都能做出那样的东西来。）

### 04 真 FDE 和假 FDE：判断标准只有一条

**Q：上次在返校日的时候，杨攀说觉得国内很多时候把 SA、FDE 换汤不换药，就纯粹是外包那些脏活累活。现在真正能懂服务又懂模型、能做最后一公里落地的国内 FDE，有那么多吗？你怎么看？**

我觉得大家很容易把很多东西都装在一个概念里边，沾点边就往里靠——"它不就是什么什么吗？"然后就很容易混淆。

我们刚才讨论的是 agent：agent 就是模型加 harness，对吧？它形成了这个 agent 产品，有了这个能力之后，进到一个具体的公司业务里，是人在使用它、把业务用它跑起来。这个过程中有一个落差，不同人使用起来效果差异很大。**所谓 FDE，是我去帮你把这个落差抬起来，让 agent 产品和你的业务结合的时候能取得很好的结果。**

而现在很多人在做的所谓加引号的"FDE"，其实是：你公司有什么需求，需要用 AI 开发这个功能，你不会开发，我带团队过来开发，开完之后就走了。这个东西对那家公司来说没有填平落差——落差还是那个落差，团队走了之后，它的人用起来还是不会用，不同人用起来还是有差异。那就不是 FDE。

**FDE 应该是形成了落差的填平**：让这个组织在使用 agent 产品的时候，对自己的业务有了更深的理解，agent 进来之后如何运作也有了更好的体验。我理解是在做这件事。

昨天看了一篇文章，是一位之前做 toB 的海外企业 CEO 说的：不可能人人都普及。不可能说人人在用 agent 的时候都达到同一个水平，你不要指望剩下那 70% 的员工都有很好的 AI 使用方法和能力，不可能。

**你只能尽可能地让那 5% 用得最好的人，给那些人提供自动化。**

还是一键——就像他以前用 toB 软件、用 SaaS 的时候，点那几个按钮，他其实根本不理解那个流程和方法，他的任务就是把这几个按钮点完。AI 就是下一步，让他少点几个按钮就完事了。人的认知在这方面，他觉得是不可能填平的。

### 05 填平落差的三条路

顺着这个提炼一下，也就是说有三条路：

**第一条路**：agent 来了之后，企业的人去试用，总有些人用得特别好、有些人用得不好。用得特别好的就是那 5%，他们跑得很快，做了自己的系统优化，其他人再去用优化之后的结果，效果就好了。

**第二条路是培训**，来提升大家对 agent 产品的认知和使用体验。当然不可能人人都培训，但有总比没有好——或者说，原来你连 1% 都不到，我帮你把那 5% 挑出来，剩下的人的认知能提升多少算多少。

**第三条路就是 FDE。** 你培训来不及，自己的人还没长出来，或者那 5% 还没摸索出来，那 FDE 就是 agent 产品带着服务直接进来，把你的业务现场摸爬滚打一遍，给你摸索出一条最佳实践之路，其他人跟着用。

这三条路走的都是同一件事：**agent 产品加上你的业务，中间那个落差如何填上去。**

### 06 零一万物学 Palantir：培训 → FDE → 把自己抽离掉

我下礼拜要访谈零一万物的马杰。零一万物不做通用大模型之后转向 toB 的垂类服务，他们走的应该就是刚才说的"二加三"——他对标的 Palantir 就是二加三。

**先去给人家做公司内部的培训，培训的过程直接是带着 Palantir 的东西在用的。他说培训完之后的转化率大概在 75%。然后培训完他再入驻 FDE，而且 FDE 在他们公司里面很多都是有股权的。**

FDE 最终的指标，不背销售指标。**他衡量 FDE 成不成功的唯一指标就是：你不是陪伴用户越久越好，而是你在了之后再抽离掉，客户还是能带着你的脑子去运转。**

他们大概是这两层。现在觉得，这是一个还不错的实践方式：每年的毛利非常高，而且很多都是复购。

### 07 齿轮的速度差：为什么传统行业反而更容易出效果

这里你能感觉到那个速度的不匹配。技术的发展特别快，两三个月就要出一个新东西。组织变化的速度肯定没有这么快——不可能技术一出来，我组织马上调，没有这么玩的。组织相对慢一些；那组织中的制度、整个的利润和利益分配、商业结构，这些东西就更落后一些、更慢一些。

它像齿轮一样，小齿轮、大齿轮，速度不匹配。这个不匹配的过程中就有一个速度差，就要看各个组织如何去调整。刚才说的那件事，其实就是：进到一些转速比较慢的企业里，我拿着快的东西进去，如何把你的速度提上来，配合上最新的技术发展。

他们很有意思。之前我们做 toB 的时候，很多人都以为提效最快的是内容行业、生成类的行业，比如内容、影视。但他们——不管是零一万物还是 Palantir——全部都挑传统行业。比如零一万物跟养鸡行业在合作。

我理解是：**传统行业出效果快。** 如果你去内容生产行业，你进去以后会发现你用得还没他们好——因为他们落地非常快，链条非常短，反馈也非常快，飞轮转起来非常容易。

而传统行业你更容易出效果。**越传统越容易出效果，越容易砍出产出效果，越容易让甲方为你的价值付费。** 我理解是这样。

### 08 从内容到产品，以及 AI 改不动的那一段

**Q：回到刚刚李继刚给我的 prompt——这半年你有什么新的认知？我觉得你很有意思，因为过去我跟归藏应该有一年没见了，你那时候刚出来，那时候你还没有做自己的 skill，但今年你好像在做自己的产品。所以你的认知差别应该是最大的。**

我自己行为上的变化是：去年在做内容，今年在拿内容带产品。而且产品还不赚钱，还是不赚钱。

但整个流程确实发生了很大的变化：我在找能落地的地方。去年其实是很难落地的，今年能落地的地方变多了，我自己能做的事情也变多了。我的变化就是做的东西越来越多。

但你说做东西有什么用？我觉得还是有问题的——就是刚才说的，在用的时候、或者说在变现的时候，还是有一些难的地方。而这就到了一个 AI 无法改变的节点：**你的渠道、你的支付、你的财务，这些跟现实的耦合是非常深的，所以你没有办法去改变和提效这部分。**

于是就造成：我往前走了一步，内容带产品、产品带内容都做了，但在商业化和变现上还是有点麻烦，AI 介入也很难受。

**Q：你为什么笑？**

因为上次我们合作做那个 Claude Skill 的网站。你知道我们这个东西从想做到做出来，整整花了两个月。

为什么这么久？因为你要把它做好还是挺难的：要不断迭代，要拉团队，要找到一个差异化点——肯定不想再做一个 AI slop 嘛，得有人去把这个东西挑好，很多细节要改。中间还有一些事。

关键在于，我把钱打到张师傅账户上这件事情，也花了两个月——因为他在搞新的公司、新的形式。整个节奏就是很慢很慢。

我最近也在尝试能不能跳出 KOL 那一套，跳出"内容付费、接广告"这样的商业模式，改成从自己的产品、自己的迭代结果去收钱。这个过程中你就会发现：一旦走上正规的交付和支付渠道，**非常、非常麻烦。**

所有东西都要重新学：开票、你的资质、你的公司，每一件都得你自己跑——因为很多东西都是法人去盖章签字。你比如说要去一趟银行或者去某个地方，一天就过去了，这一天你什么都干不了，你就在路上。

**这就是 OPC（一人公司）的一天。跑财务跑一天，开票开一天，签合同签一天。**

那天有件离谱的事：签那个合同，对方那个合同永远有问题。我签了八份，一共 120 张纸，我盖了 80 个章，没有一次是对的。我的一天就在盖章。

所以就会有服务公司去服务这件事。这些代理是不会消失的，**AI 做不了这些东西。**

这就是刚才说的制度和技术之间的齿轮速度：制度是非常慢和稳定的，技术这边是特别快在变化的，两者有个速度差——而服务就在填平这个速度差。

甚至我觉得，AI 之所以在 coding 上跑得快，一个是因为强化学习，另外就是 **coding 这件事不依赖这些东西**：你做完产品就好了，产品之后的分发、付费、政府关系、安全，全都不需要。所以 coding 才快。

所以这时候你就越觉得 Stripe 牛逼。（是啊，但牛逼跟我没关系。）Stripe 真的是个很强的 infra——它在销售的后链路上，在收款、财务、对接这方面，把自动化做到了极致。支付就是 Stripe，然后银行就是 Airwallex。**用过 Airwallex 的人就不会再想用别的银行服务，差太多了。**

但你看，等你从这些定制完了之后走到办公领域，你会发现就开始有一些结合了，这时候阻力就明显变大了。

**Q：所以你是以这个姿势从内容转产品的？所以你上传 GitHub 是在积累 reputation？**

我觉得是能力问题。以前 AI 做不到这些事情，现在能做到了，我自然而然就去做了。不是我不想做产品，是因为之前我没有能力在一个人的时间里既兼顾产品又兼顾内容，效率达不到。

在 Claude Code 出来之后，后面一直在发展，比如 Codex 之类的——我的资产、我的工作流都沉淀到 skill 里以后，我的自动化程度越来越高了。

比如我为什么发视频的频率越来越高？因为**我只用录，录完我就不管了**。录完我就直接去干别的了，回来一看，处理完了，我就发。非常简单。所以我觉得是生产力带来了非常强的变化。

### 09 Skill 能赚钱吗：to C 收费是个悖论

**Q：我真的是门外汉、小白——现在做 skill 有赚钱的吗？问橘子，橘子离钱最近。**

赚是赚，但赚得不多，一直在探索。

因为 **to C 没办法向 to C 的用户收费，这是一个悖论**：他用 skill 本身就要消耗 token，你 skill 还要再收费，那你不能让他试用吗？他试用也要消耗 token。所以你必须让他以非常低的成本、通过非常多的渠道用到这个东西，才能让你的 skill 产品更快地扩散。

同时，skill 的架构决定了你没办法收费，因为它不保密——下下来就是开源的。

所以 skill 后边的形态一定会有一个新东西。以前是提示词，后来是 skill，再往后应该还有一个新的形态，可能是 plugin，不知道。

**我现在的方式是：跟 agent 厂商合作。**

agent 需要用 skill 这种方式让用户快速感知到它的能力和价值。你比如说我只做一个"派（音）"，我拿一个派给用户，用户就很迷茫。但如果我直接给你推一些最优质、最顶尖的 skill，他拿这个 skill 做出结果来的时候，他会把这个能力和结果归到 agent 产品本身上。

那么你这个优质的 skill 或者 plugin，带来的价值就是**你在为它赋能**。用户不会想到"你这个 skill 牛逼"——当然厉害的用户会想到，但普通 C 端用户就觉得"你这个产品厉害"。

那你既然用了这个东西，给用户产生了更好的想法、让用户觉得你这个产品厉害，那我觉得你自然应该在这方面下功夫，以及笼络这些优质和顶尖的创作者。

核心问题是**怎么把这些东西筛出来**：怎么把优质的 skill 也好、plugin 也好筛出来，让用户快速感知到，快速把这个插件/skill 内化到你的产品里，让他感知到这是你产品厉害，而不是这些东西厉害。这也是一个非常复杂的过程。

而且，**要学会用一个 skill 还是很难的。**

昨天我用了一个 skill，很难用——它很厉害，但我要用它的话，我把一篇文章给它，让它帮我做一些事情，然后它给我的、让我接下来做的事情，一步比一步难，最后我就放弃了。

因为一个 skill 本质上就是一套软件，只是它没有界面。而且每个人也不需要那么多 skill，重点还是你要想清楚你需要什么东西。比如 PPT 这个场景，我就是需要 PPT，那就比较简单；但你真实的需求是非常复杂的。

我觉得 skill 能解决的问题，在我看来更多是一个**模板**——我看一下这个东西能干嘛。最终我要用到我的实际工作中，我一定得自己定制一个 skill。你看你为什么暂时不用别人的 skill？就因为你真的要进入自己的工作流里面，你不可能用别人的 skill。

**这就是个人的 FDE 化。**

### 10 跟大厂合作：入库地狱

**Q：所以你跟这些 agent 厂商是一次性买断吗？**

是授权加赞助。因为本身开源嘛，所以可以用赞助开源的方式，也可以用授权的方式，同时进行，相对比较双赢。

但即便如此，你想他盖章盖八次，就说明这个阻力还是很大——**本来一个授权 license 可以 scale 的事情，变成了一个无法 scale 的事情。**

而且这是一个新东西，在一些 toB 大公司里边是没有对应的流程和章程的。那你就需要跟他们频繁沟通交流，或者用一些别的方式。（也建不了 SOP，因为各个厂家都不一样，所以就很麻烦。）

跟大厂合作就是这样。你知道我们去年大概也是八月的时候，某个大厂要采购 ListHub（音），然后开始办入库。这个事情办了多久？**大概是在上个月终于入完库了。然后入完之后，他们那个项目可能都不存在了**，也没有走后续流程。

我之前是用了两个月入完库，结果我旧的主体出了点问题——因为是个体户嘛，主体承载不了更多的税，我得换主体，好，重来。重来我就不想弄了，弄不了了。

**Q：所以会不会出现针对这些 OPC 的服务公司？**

我觉得这个是很有价值的。但也不好服务，还挺专业的。我觉得需要——你在后端处理的时候需要人来处理，但跟用户沟通的时候是可以让 agent 去沟通的。

你看，刚才我们说飞书 client、企业微信 client 现在都出来了，它对外提供的是 agent 的方式，直接去调用它的能力去发消息。那企业的这些流程——比如 SOP、比如入库流程——是不是也能提供一个标准的 client 出来，然后跟你的 agent 直接去协作，降低一部分跟人沟通的成本？不然就是反反复复"你这个章盖错地方了"。

核心问题是它原来就有流程，跟部门有关系，不只跟企业有关系，跟人也有关系，甚至还有外包，外包的外包。而且还有不同内部组织的问题——不是简单的"跟这个部门可以，跟那个部门就不行"。

最近我们发现，跟一个台湾企业要采购，也是先入库。很多都有类似的软件，因为他原来就是 SaaS，整个企业都依赖在 SaaS 上。

而 SaaS 又带来更多问题：有时候 SaaS 可以免费试用，因为 SaaS 没有成本；但 AI 软件一般都没有那么多免费试用。所以他要想用我们的软件，就得先签个合同，然后才开始试用——那个流程也很长。

### 11 SaaS 必死，软件必死

**Q：讲到 SaaS，我刚刚又跟橘子聊到，之前在返校日也聊过——未来手机上的 App 是越来越多还是越来越少？他说 SaaS 必死，软件必死。**

SaaS 本身就是对软件的一次革命——软件不再重要了，我卖的是服务。

所以为什么手机上 App 越来越少？就没有必要了。整个 App Store 生态已经不繁荣了，没落了。

### 12 vibe coding 的人已经很多了，但他们发不出去

包括最近——你们在座的可能都不刷抖音，主要是我在刷——刷抖音的时候你会发现，我们一直以为做 Web 的人在变少，一直以为不多，但其实越来越多。

但大家现在的 gap 是什么？**他做的东西没有办法被别人用，他只能给自己用；同时他也没有一个好的地方去发这些东西。**

你说我 vibe coding 出了一个东西，然后你发到抖音上，抖音给你限流了，甚至直接给你号封了。

为什么？因为我们现在所有这些东西都依赖那些旧的互联网 1.0 时代的基建。而 2.0 时代的基建是高度封闭的，它不让你发布产品——**发内容可以，发产品不行。** 各个软件的核心驱动力就是：你最好别在我这儿发产品，不要抢我的用户。任何产品都不要发，好游戏可以，其他不行。都是防御心态。

这就造成了很多人做的东西发不出来。因为他不像我们这些从互联网 1.0 时代过来的人，有很多种方法可以帮你把东西发出去——他们根本不知道这些东西怎么发。AI 给了他一个网页，他甚至不知道这个网页是什么。之前不是有个笑话吗？他把网页地址发给了其他人，那个地址是 127.0.0.1。

所以我们的基建、我们整个的这套东西，我觉得都没有跟上，但是整个做 coding 的人群其实已经非常大了。

所以我觉得小红书的小工具和 RED Skill 是一个比较好的东西：它还是维持一个封闭的状态，但是它给了你一个渠道，开了一个口子。

### 13 GitHub：AI 时代的基建要重来一遍

说到形态——1.0、2.0 以及到今天的 AI。比如 GitHub，它是标准的互联网时代那种"以人与人之间的协作为基石"垒出来的一套机制。

但你现在 AI 写代码，呼呼地三万行、五万行、十万行代码的提交，而且每次改动三五十个文件。**人是审阅不过来的**——你有多少人能看懂那个代码？等你理解完这一轮，下一轮又堆积了好多。

所以这种不是基于人与人、而是基于 AI 的提交修改的新机制，我理解也会有一个新范式的代码托管平台。比如 Cursor 不是刚推出了 Orange（音）吗？它其实就是做了一次转变。这一类的转变，我觉得未来会比较多——**以前我们习以为常、一路用过来的 infra，在今天会重新来一遍。**

所以 GitHub 很重要。我觉得微软最重要的翻盘点就是 GitHub，但是……微软太垃圾了。我们跟微软合作到现在，那个后台都很难用，任何功能没有他们销售帮忙搞一周都搞不定。昨天还宕机了几个小时。

**Q：这是不是历史包袱？那么多人的代码都放在上面，他不敢大改。而新的东西是从零开始的，我管你呢。**

对，这个 gap 就不是 FDE 能解决的了，这就是范式了。

也不是不敢大改，是他根本没有意识到——这个流程可能已经有 20 年了。谁敢重塑这个流程呢？有什么 ROI？

我觉得这是很重要的东西：**git 是一个天然的、agent 与 agent 协作以及 agent 与人协作的纽带。** 你现在装任何一个 agent，什么都可以不装，但你不能不装 git。

比如很多人自己搭 loop 的时候用的也是 git。issue 和 PR，就是两个 agent 相互交流的方式——而且大家事先是没有交流过的，默认就会用 git 这个形式。**因为这个协议非常完善，而且不需要上下文，而且所有的 AI 都懂。**

比如我们的用户、Cola（音）的用户去提反馈，都会进入我们的一套后台，然后创建一个 GitHub issue。然后我们在 Slack 里派一个 agent 去监控这些 issue 去修改。大家通过这个把 Slack、Cola（音）和 git 连起来了。

我自己也是。我自己开发的那个 Cola.md（音）也是——每天他们会提 issue，我就定期用 Cola（音）去扫 issue，然后修一下，发个 release 再发到那儿。大家都是通过 git 来中转。

所以你说 git 老宕机，说微软不行也可以，但有时候也能理解：每个人都在提交代码，一改改几十个文件，疯狂地 push，而且很多都是免费的，那确实顶不住。

**可能免费的 git 也是造成现在 vibe coding 繁荣的一个非常重要的基石。** 但凡这个服务是收费的——比如刚才说的 Cursor 那个是收费的——那么它的成果和它的能力就有限了。

### 15 Agent + X，还是 X + Agent？

**Q：下一个我很好奇的问题。我看李继刚最近非常关注，你说 "agent + IM" 大于 "IM + agent"。说实在话，我不知道这个命题背后探讨的本质是什么，它重要的原因是什么？**

那个是在讨论**到底以谁为中心**。

**以 agent 为中心的话，是我把所有其他功能都装进来。** 比如我把飞书 client 接进来之后，我的对话一直在 agent 中发生：我需要给同事发一条消息，我就在里边说"给谁发个消息，提醒他几点交什么东西"，这个消息就直接过去了，我根本没有打开那个软件。这是 agent + X。然后 X 不断增加：IM 功能、文档功能——我不用打开 Office 了，我在这里直接说"帮我生成一个 Word"，它直接就写好了，我没有打开 Word。这是一种使用方式：agent 加上各种原来的功能 X。

**第二种形态，是以前的互联网公司**。比如 Office，它已经活了那么多年，卖得又很好，它自己就是 X，它也想结合 AI。它怎么做呢？X + agent。它里边会打开一个对话框，你在使用的时候，你这个数据要生成图形等等，你在右边一对话就出来了，也可能很好用。但它的逻辑是把 agent 的功能注入到原来的 X 里边。

那就会形成很明显的两条路。到底哪条路能走出来，现在是未知的。

**以前有基本盘的互联网公司一定会选第二条路，他不可能放弃自己的立身之本。** Office 也好，微信也好——你看微信的小 V，我理解就是 X + agent，agent 会进到微信中，比如读取它的上下文、给你更好的建议等等，它一定会往这个方向发力。

而另一套做法，比如飞书现在走的，在我看来就是 agent + X：以豆包为核心，所有东西都往里装。所有的 X 化整为零，住进去，**一切以 agent 作为跟用户接触的界面和入口。**

你想做的事情，两条路都能完成，相当于一个向左走、一个向右走，最终都在山顶见。哪条路更好？这是我在琢磨的事。

我目前的感觉是：以前 X 的方式就像手机里有很多 App，每一个功能点我都打开一个 App 去做；现在我只需要一个 agent，里边可以调很多 App——App 变少了，但 agent 功能变多了。所以我个人现在觉得，**agent + X 可能是后劲更足的一条路。**

我觉得它是有限制的。为什么一定要是 agent + X？**因为 X 动不了。**

X + agent 一定是别扭的。比如微信里的小 V，它一定别扭——它是嵌在原有的 X 中，跟你原来的使用体验很割裂；你的用户也不一定为这件事做好了准备；然后你还有原来用户的负担。

现在 AI 成本很高。你为了给所有人尽可能提供免费服务——很多旧产品的核心就是免费服务——以前你能用广告、用商业推广 cover 住成本，但现在你显然 cover 不住了，因为以前的服务器成本多低啊，而现在每个 token 都是成本。所以他没有办法以一个非常合适的方式加进去。

同时，旧的组织结构里，大家的 agent 能力水平是参差不齐的，他加的时候无法理解这套东西；旧的基建也可能有问题。这就造成它达不到专门做 agent 的那种能力水平和用户体验。

**Q：去年跟橘子聊过，橘子当时做了一个思想实验，你还记得吗？**

对。手机这个地方，我们现在习惯了花两千块、四千块、八千块买一台手机，里边有很多 App、有 App Store。那如果真的往未来看，三年、五年之后，我们有了很先进的模型，agent harness 也做得很好，我为什么还要点开手机、解锁之后去点各个 App 呢？

**为什么不能就是一块屏幕，我直接跟它说话？** 给谁发一条消息，明天给我添加个日历，怎么怎么样——就说话。我都没打开、没解锁屏幕，活已经干了。

这不就是 agent + X 这条路走到极致吗？这个所谓的手机就是一块屏，或者就是一个对话界面，其实就是跟 agent 的对话，它去调用各种 client、各种 skill、各种能力去分发，最终把活干了。你想一下，好像是非常丝滑和顺畅的。

### 16 但只有 chat 是不行的：人永远需要一个目录

手机这个场景有个问题：**手机不是用来干活的。**

不说干活，就说你有个事要做——它能做到。包括现在你看那些 AI 助手，它也能帮你订票、订酒店，其实能做到。

但我后来发现一个问题：**人的记忆力不足以支撑这件事情。**

比如我订了一些票，我可能明天就忘了，我是需要看到那个界面才能想起来。包括我笔记库里有一堆文件、上千条笔记，我需要看到那个东西才能想起来——我自己想不起来。

（你的输入框放不放一个 work tree？）对，你根本不知道自己有什么。**人类永远需要那个目录、那个界面 UI。**

它变成一个仓库。chat 可以解决一切问题，但你要看着仓库，你才能想起来我要干嘛。

所以一个大的 dashboard，我觉得是接下来每个软件都一定会做的——**只有 chat 是不行的。** 把所有 chat 中的事情、代办、遗留未完成的工作，全部在 dashboard 中呈现。

它其实是说：我不依赖以前那套原来的 UI 了，但我一定要建立一套新的 UI，而且它是一个**动态的 UI**，随时变化的。

### 17 A2A：人与人之外的第二张网

**Q：我记得你是跟杨攀聊完之后，特别笃定地在群里发了一句"未来就是 agent + IM"，为什么那么笃定？**

X + agent 我感觉是在原有结构上边生插了一个 AI 能力，这种生插和原有的体制是有点变扭的——**它不够原生。**

而 agent 作为入口，比如我说"我要做一个什么 PPT，什么场景、需要什么风格，这是我的文稿"，然后就出来了。你习惯了这个入口之后，你不会再想到"我现在要打开一个软件再去排版"；这张图不好，你就跟它聊天说"你再把图给我换了"。

这两条路径，你自己实际体验一下，好像是前者更丝滑一些，**更符合一个人想象中的未来——我在跟 AI 协作做事情时的一种姿态。**

**Q：我直觉的感觉是，微信那么多年没被打倒，是因为它的关系链。这个关系链如果未来被迭代的话……**

我觉得可能有一个模型可以聊。

以前是人对人，人对人这个关系网，微信那张网肯定是无敌的。现在的变化是：如果未来发展好了，每个人都有自己的 agent，那就是除了人与人（H-H）以外，还有 H-A-H 和 H-A-A-H 这两条新的对话之路出现了。

那么 **agent 与 agent 之间关联的这张网，在原有的网之外，还是在之内？** 我觉得这是值得思考的问题。

有没有可能有一张新网，这张网中的节点主体一部分是人、一部分是 agent？比如橘子的 Cola（音）和我的 Cola（音），我们都已经有大量的上下文、沉淀、对话风格，包括联系人，我们的关系都沉淀在里边了。这时候我只要跟它说一句"提醒一下橘子，明天下午我们要聊一个什么事情"——我一句话说完就过去了，我是在跟我的 agent 说，但我的 agent 会找他的 agent 去 book 时间、去发邀约。最后橘子在 dashboard 里看到了他的 agent 给他说的这件事。

**这种对话已经脱离了人与人之间原来的交流网。** 这张网能不能形成？

在今天这个时点来看，agent 还比较少，起码没有做到每个人都有一个。这也是个问题。

而且比较受旧的互联网基建拖累。现在比如在一个公司里，大家都用 Slack，Slack 里其实每个人都有自己的 agent，其实是可以有这张网的——你会发现 Slack 那个界面很好，包括 Claude 的那个 tag 在 Slack 里面非常丝滑，因为它有上下文。但如果我们抛开以前的 IM 去新建一个网络：一是上下文就丢了，二是新建一个网络非常非常难，有很多基建的东西弄不过来。我觉得这个阻力很大。

我们其实在 Cola（音）里试过一版：让两个 Cola 去聊天。但会发现**用户学不会，没有人用。** 因为这是一个新事物，而且很抽象——"我的两个 agent 在聊天"，我看不见，就很抽象。哪怕有一些 dashboard，我也觉得很抽象。

后来我们发现，用户特别是 C 端用户，他能接受的概念非常简单、很小白。比如微信，我就是看到这个界面，我在聊天就完了——从 QQ 养成的习惯迁移到手机上，就这么简单一件事。你让他再加一层，就很复杂，他理解不了，然后用不起来。可能得从新一代开始。

而且两个没有上下文的 agent 之间是没有区别的，而上下文又很难拿。

### 18 别人的 AI 味，和自己的 AI 味

我还发现一个现象：**人们对自己的 AI 输出的文字接受度还是比较高的，但对别人 AI 输出的接受度很低。**

所以中间会经历一次"翻译"——别人写的公众号文章，要经过我的 AI 转述一遍再给我。因为大家都觉得别人的 AI 写的是 AI slop，自己的 AI 写的还行。特别奇怪，但确实会这样。

我觉得总体来说，**人还是比较喜欢人、喜欢人话的。** 为什么大家都觉得 Opus 4.6 这个模型好、之后越来越差？就是因为它说人话，后来的模型不说人话了。

语言是很奇怪的东西。语言不是随机组合，每个字的排列背后都有一个心理模型。

所以最近他们给模型加水印之后，大家为什么这么反感？那位反复强调水印不会更改输出质量、不会更改你的文案。然后 Claude Code 的一个员工写了一个示例，向大家演示水印是怎么工作的——结果他那个示例里，**上水印前的文案和上水印后的文案完全不同**。他自己还在那说"你看，没有改变你文案的意思"，然后下边评论："这哪没改变了？每个字都不对，意思完全变了。"

比如在严肃场景里，法律、合同上面，你换个词就全变了，因为上下文变了。大家的感知是变了——你在读这段文字的时候会很明显地烦躁。**一句话里多一个字、少一个字，传达的东西是完全不一样的。**

### 19 现在的 AI，还只是一把更好的锤子

**Q：当时你们做的那个"终极推演"——也谈不上终极，只是往前多试着走两步——你觉得最后会是 toB 场景跟 toC 场景分开，还是一张新的、大一统的网？**

我觉得我们期待的是电影《Her》、是钢铁侠的贾维斯：一个 AI 助理就在我们旁边，所有的上下文他都知道——你的健康数据、你每天聊天的上下文，他理解你跟别人的关系，理解你的认知模型和你的世界观。你有想讨论、想思考的东西时，他能跟你做一些碰撞。大概是这么一种协作关系。而在人与人之间的连接上，他是一个辅助的身份，能帮你完成更高效的连接和更深刻的看见。

但现在还没到。**现在的这种东西，更像是一个更好的锤子。**

当前大家还是把它视为一个工具：以前拉了一根网线过来，我们成了互联网公司；现在拉了一个 AI 进来，我们要成为 AI 公司——还是把它视为工具。

但我觉得这一次和互联网那一次有一个本质的不同：**它真的出现智能了。** 当然没有意识，但智能出现了。拉网线是没有智能一说的，它只是让信息传递变得更高效。所以这一次的本质不同在这里——只是我们期待的那种画面、那种境地，还没出现。

**Q：Cola（音）那时候的尝试是别人进不去，还是进去了之后发现别人的 agent 上下文不够？**

我觉得首先是：我们跟一个人聊天的时候，"想到要引入另一个人"这件事，你就得拉个群——这是一个心智，而这个心智本身就很难。

**群聊这件事，在中国之外都不流行**，美国那边都没有群。这些看起来我们习以为常的东西，其实都是学来的。所以"我在跟我的 Cola（音）聊天的时候，我 @ 一下李继刚的 Cola"，这个行为就很难学。

这种事一定得有好处，他才会学。要么是它确实能大幅提高我的工作质量和效率，要么是它能带来更多的、比如内容消费上的愉悦感。

**人要想学会一个东西，一定得有一个 trigger，一定得有一根胡萝卜放在前面才行**，要不然就很难。

### 20 被忽略的另一半：AI 内容消费

但我最近观察到一个现象：**我们这波人关注的都是 agent、工作效率、生产。而非常多的 C 端用户是不需要工作的，或者说没有这个需求。**

之前很多人说——我发一个什么功能，下面总有人抬杠说"不就这"，"还是没到我给他发句话他就一下给我做好"。我经常就会反问：这个时候为什么要你来发那句话呢？谁发不是发呢？凭什么是你呢？你现在都没工作。

这些不需要工作、或者不需要用 AI 工作的人——他们的工作要么很简单，要么就是普通白领，有没有 AI 都无所谓，本来活就干不完，或者本来就没得干。那么在他们想象中，AI 对他们产生最大的影响是什么？

**Q：AI 玩具？AI 视频？**

都不是。我觉得我们这波人是割裂了两个形态。

**Q：李继刚你会频繁关注 AI 内容消费在用户里的渗透率吗？**

我没看那个统计数据。

不用看统计数据，就凭感受你会发现：**在内容消费上，AI 的渗透率发展比在生产力上真的要快得多得多。**

现在 AI 短剧的渗透已经超过 8 亿了。以前是有人不看短剧的——短剧尬、过于降智、过于无脑。但有人喜欢无脑，同时相当多的年轻人、有内容追求的人是不看短剧的。可现在，越来越多对自己消费的内容有要求的人，也在看短剧。

前阵子我试了一下。刷抖音的时候出来一个短剧，名字早就忘了。我看完这一集，然后我脑子里分了两个我，我在观察我是怎么想的：**"要点下一步"——下一步需要下载 App，我真的去点了下一步。** 我在观察我自己，真的从一集一集地看，每一集都很无脑，那个剧情让你觉得是一个小学生写出来的。但是它那个钩子，一集钩一集，钩的是你的生理。

我清晰地知道自己在一步步往前走，我知道有人在引导我，我也顺着他的引导走。就很微妙、很玄幻——脑子你控制不住。

而且高质量的越来越多。以前短剧补不上的那些东西，比如复杂的剧情——**短剧正在变得网文化**：它可以日更，同时又有长篇的剧情和非常复杂的架构，不再像以前那种无脑的。AI 给你画架构图、给你生成世界观，生产效率变得巨高。

我觉得这整个是一个非常大的产业。**内容生产的质量在这个时候变得非常高，同时速度也提升了。**

如果技术继续发展，这个门槛进一步下降、下降到零——每个人脑子里都有个想法，每个人都有个幻想：你想御剑飞行，你想当神算子。当然讲故事这件事我觉得还是需要人来讲，但有了 AI 的协助，门槛降下来之后，**你给它一个种子，它给你生长出一棵树。**

第二步是发布。抖音的基建做得那么好，短剧平台也好，大家都可以上传——海量涌现。当然有大量可能只有 60 分的，但也会从里边冒出来 89 分、90 分的，而且越来越多。

（现在也很难衡量什么分，真的看一下《牛来》（音）就知道了，这个"分"还有没有关系？）

蒋尚克（音）说的：**两小时的电影的好故事是好故事，两分钟的短剧如果是好故事，它也是好故事——跟时间没有关系，跟创作质量没有关系，跟人也没有关系。** 贾玲自己也疯狂刷短剧。

### 21 三个世界的叠加：原子、比特、token

就是说，技术到底给我们带来了什么东西？

如果技术发展到这个程度：每个人以前因为专业门槛限制、各种现实约束，没办法去弄，只能在脑中想一想；而现在这个"想一想"真的能变为实际的生产、能交付出去。有可能它就不了了之了，只是把自己的想法做出来而已；但也有可能突然被很多人看见。**他多了这么一个可能性，我觉得这挺好的。**

第二个好处，我前阵子刷抖音的时候看到一个救生衣：游泳的时候不是会扔救生圈嘛，他把大疆那种四引擎飞行装置加上去，那个救生衣能在天上飞，直接飞到你头顶啪地落下去。这比扔救生圈好太多了——扔得离太远、没抓住还得再扔，可能就错过时机了。你就会觉得，科技好像就应该这样。

今天广西那个洪灾，大疆调度救援物资的时候，效率比之前高一万倍。

我觉得，可能我们要对生产力和工作效率保持关注（agent 的 coding 这块），但**更多人需要的是消费。** 不管是漫剧还是游戏——最近很多人开始用 AI 做游戏了，Steam 的游戏增长也非常快，因为确实有很多人用 AI 能做出非常好玩的游戏，因为他本身就有能力、他自己也玩。包括短剧，在内容消费上还是一个更大的增长。

因为大部分人其实越来越没有工作了，不需要那么多工作。同时，一部分人的生产力被解放了，好内容的生产会越来越多。当然不是每个人都能讲好故事，但**能讲好故事的人会越来越多——有资格讲故事和能讲好故事的人越来越多。** 很多擅长讲故事的人只是没有被看见，现在有这个机会被看见了。

所以我感觉整个行业很割裂。那波人在搞消费，我们在搞效率，而且大家平时是**默认另一个世界的人不存在的**。他们不讨论 agent，也不讨论 coding，你只能看见你能看见的。

顺着这个思路来做个模型：如果我们拉一个三维的轴——一个轴是原子世界，一个轴是互联网的比特世界，还有一个轴是 token 世界，这三个世界是叠加的。

token 世界就是我们现在的模型能力、harness、agent 在不断发展；互联网世界是我们都很熟悉的、有完整基建的那个世界。

**现在发生的事情是：AI 世界发展的技术在往互联网世界靠。** 比如帮你生成短剧、帮你写小说——更多是两边相互在靠、在结合。这是一个方向，包括刚才说的效率。

**还有一个轴的结合，是 AI 世界和原子世界的结合**：就是刚才说的会飞的救生衣、大疆无人机去灾区救人。它的 AI 能力去结合原子世界的改变——对大众、对我们每个人而言，那是另外一种"AI 在我们身边"的体验。

包括最近在搞的癌症研究，AI for science 也是很好的例子。

有个播客叫《福如天地》（音），找了一位在美国做临床药物研发的博士。他说 AI 带来的药物革命，现在变成了一个什么问题呢？——**临床实验巨慢，药物研发巨快。**

他的意思是：可能在未来三五年，我们会发现大量疾病被治愈或延缓。因为 2021、2022 年基因编辑和蛋白质结构预测技术出来之后，大量的人在用；到今年、再过几年，他们大量的药物临床实验做完了，就会大批量上市。到三五年后，相当多的疾病会被治愈。

**涉及现实就会有很多延后，但它一定会在某个时间点直接爆发**——你可能在三年内会发现："怎么这么多新药？怎么这么多病都有得治了？"

最近中国的实验猴都涨价了，供不应求，说明 AI 的这种实验室已经多到了抢猴的程度。

### 22 A2A 社交：缺的不是懂你，是那张网

**Q：我们刚讲的一个是效率工具，一个是 AI 娱乐。还有一个我一直想不明白的是陪伴跟社交。你不是也看过很多 A2A 社交吗？他们都打着一个概念：但凡这个 agent 拥有你所有的上下文，他就可以找到全世界最符合你的 soulmate，匹配完之后人再进入，然后双方交流。我听下来很 make sense，如果有这样的东西我会用。但你们好像都不看好，为什么？**

它有两个假设。

**第一个假设是：这个 agent 需要拿到你所有的上下文，足够懂你。第二个假设是：他去全世界寻找，跟别的 agent 对话，帮你找到最符合你的人。**

你去看看这两个假设现在在哪里。

第一个假设——agent 不断累积上下文、更懂你，模型能力在提升，harness 和 memory 的架构在提升，这块是越来越好的。

但第二个假设——agent 的世界、那张网，就像刚才橘子聊的，**还没成型**。你怎么去发现全世界？比如 Cola（音）里有我的，也有他的，他能看到我就了不得了，他能看到全世界其他人的 agent 吗？这两点还没连接起来。所以那个就很难搞。

包括上下文这件事，很多人根本不知道自己的上下文在哪，你去哪找他家的上下文？

我现在对人与人的关系又有了新的认知。比如我跟我老婆看电影，我俩喜欢的电影都不一样。**agent 怎么知道你们两个是合适的呢？你用什么标准来判断这件事情？很难——你自己都不知道。**

比如有些人，他们在认识之前各自有各自的爱好，认识之后才互相知道对方的爱好，这个也很有意思。而不是说我找到两个人，让 AI 判断一下你们爱好差不多、有点像，就给匹配——**这个是反的。**

所以缺的是那张网。首先我们默认每个人最后都有一个 agent、有充足的上下文，那么缺的就是那张网。

我觉得到那个阶段，这张网就会出现。**当第一个条件已经足够好的时候，第二个条件就会冒出来**，就会有人去解决 infrastructure 连接的问题，agent 世界的互联网就会出现。

### 23 界面回到只有一个聊天，但背后的基建完全不同了

刚才提到的 Grok Bot（音），它是一个很激进的想法：**界面什么都没有。** 你在不断创建 agent，每个 agent 就是一个任务，界面上就是一个聊天。

它回到了原点。从原来 ChatGPT 界面上就是一个聊天，到了 harness、到了 Codex，里边一堆按钮、各种各样的功能；现在又回到了只有一个聊天。

但这后面所代表的基建已经完全不同了：**它给你分配了一个永久性的虚拟机，同时连接了所有能连接的服务。**

而且它的连接方式是这样的：它不会生硬地弄一个界面让你去连接，它只会在某个任务需要这个东西的时候，自己弹出一个按钮——"好，你点一下，连接一下"。一键授权完了以后没有任何干扰，你好像忘了"你需要连接和授权"这样一个操作。

所以两个点：一个是这种极简的连接和上下文获取，加上持久的云上服务——每个人都有虚拟机；另一个是"派（音）"和 DeepSeek Harmony（音）代表的进展，就是我们说的**忒修斯之船，自迭代和自进化**的那个逻辑。

你能理解 Grok Bot（音）为什么要这么做：因为它确实对 C 端用户来说更好理解，同时使用场景也更多，比如它有 iOS App。因为它是虚拟机、在线上，有你所有的上下文，而且上下文获取非常简单，流程做得很平滑——这样你就完全可以在手机上进行任务、进行迭代、进行处理。

它达到了 agent 的下一个阶段。对 C 端用户来说是下一个阶段；对高级用户来说，他们有自定义的需求，那是另一回事。

**Q：它怎么拿到你所有的上下文呢？它不是一个云端的虚拟电脑吗？**

你本机的笔记也可以传。你在本地的时候它会读，读完之后把信息拉到云端去。它应该不主动扫，需要的时候会让你做一个同步——当前任务下它会同步这个文件夹，如果涉及到这个文件它会同步一次，不是全部同步。

所以这里存在一个矛盾：一条路是"我需要什么就找什么，拉到云端"——你本机上有 100 个文件，需要用到三个就上传三个；另一条路是 agent 在你电脑里，跟整个电脑的 100 个文件住在一起，**这 100 个文件就是它视野所见。**

（也可以是混合的：你电脑开机了，你在手机上就可以操控你的电脑；电脑没开机，你也可以用。）

### 24 上下文获取：海外点一下就全在那儿，国内点开只有一个飞书

还有一个问题——**海外。**

我们大部分人其实都完成了 agent 的线上化，只不过它在哪呢？在 Gmail、Notion、Claude、GitHub、X。而且这些全部都有 MCP 了。

你会发现，我在国内用连接的时候，**一点开，只有一个飞书能连，没了。**

而你在海外的时候会发现，你用的每一个 AI 产品——哪怕是谷歌这种、哪怕是微软这种、哪怕是之前我们说的 Notion 这么封闭的——它们 AI 世界向互联网世界之间的连接就很顺畅。因为互联网世界向它开放：点一个按键，好，你的所有信息都在那儿了。然后它每次都能读，包括你所有发过的推文。

比如前天我让 GPT 每周定时去分析我 Apple Watch 的健康数据。它甚至能读你医疗服务的体检报告，以及你的病历。**这个时候，咱不说 AI 治病，它哪怕给你一些建议、帮你分析那些数据——医生不可能看完你所有的上下文，分析那些蛛丝马迹，AI 是可以的。**

**上下文带来的潜力是无限的，我们还远没有到那个临界点。**

（另一个是刚才说的"派（音）"和 DeepSeek Harmony（音）：你知道它是一个很有前景的方向、能力非常牛逼的东西，但你现在看不到它使力，太远期了。）

### 25 过去一年最切身的两个改变：语音输入法和翻译

回顾过去一年，对我个人切身影响最大的应该是两个东西。

**第一个是语音输入法。** 它确实改变了我在电脑前的人机交互方式，包括手机上也开始尝试全部用语音输入。当然语音输入是转成文字，你说的那一下，它自动给你换行、给你标 1234 的序号，排版也很舒服。现在语音输入法做得都很好了。

以前打字你习惯了；而说的时候，我会发现**在心智上是两种**：你想到哪说到哪，相当于你在跟自己对话；而打字的时候你会字斟句酌，这个词不对你会删掉这两个字、在那微调。这两者在心智上是完全的两条路。这个改变是切身的。

**第二个是翻译。** 我们之前都说语言隔离——在互联网时代我装各种翻译插件，你点一下就可以，但**"就得点一下"其实是一个很关键的一步**，很多人就不点那一下了：看到日语、看到俄语的动态，你就不看了。而现在默认就给你翻好，你就会觉得语言的隔阂真的就不存在了。

AI 确实已经在我们日常的每一天里了。

### 26 AI 看病：上下文阅读 + 强推理

刚才说医生那个例子就特别好。**医生不光是不会去了解你所有的上下文，他甚至会忽略你说的很多话。**

我们有一个用户，得了一个病，得了十年了，去找医生看过，至少十个医生吧，**没有任何人听完他讲话**——因为他讲的是个慢性病，要讲很多，医生每次听一听就说"我知道这个差不多是什么"，然后给你开个药你就走吧。

后来他跟 Cola（音）聊了很久，把他这十来年得病的感受都告诉它，然后它给他推理出来说"你可能是什么什么病，推荐你用这个药"。他拿这个结果去找医生确认，医生说：还真是。**之前没有任何一个医生给过这个 option。** 然后他拿到这个药之后吃，病就治好了。

他那个病是身体不能变胖的，营养上不来，因为肠道里有细菌之类的问题。吃了那个药之后，他已经胖了五到十斤，特别开心。

我也深切有体感。前三个月——其实是那半年——我每天都是脑雾，然后睡不醒。我不是天天很晚来公司嘛，睡不醒，觉得非常累。我以前一周跑步三次，那时候一跑步我就想吐，晕到想吐。

因为我妈有甲状腺的问题、甲减，我就一直以为我是甲减，想说也不用着急治。但我每天会跟我的 AI 聊天。后来有一天我就问它：结合我的上下文，你觉得我有可能是什么病？我是不是癌症？还是甲减？

它跟我说：**结合你的情况，我觉得你有可能是缺铁性贫血。**

我说那你建议我去查什么？后来我就真的去查了，发现我是缺铁性贫血的临界值。我现在一直在吃铁片，就真的好了。

**因为它完全有你每天所有的上下文**：你的感觉怎么样、你几点睡、你的周期是怎么样。但凡它有你足够好的上下文，那真的很准。

再比如我女朋友，她有一个老问题，所有医生一看这个问题就让她去吃一些雌激素的药、调经期。但我之前跟 AI 聊，它说这个有一个核心原因是体重——很多女生是因为体重大造成了激素问题。我说她不胖，她很瘦，BMI 也正常。然后它说：**她可能是胰岛素抵抗造成的，所以一直治不好。**

因为我爸是糖尿病，我很了解这个事情。我就让她去做胰岛素释放实验，还有另一个实验。做完发现——她的血糖为什么一直没发现问题？因为她年轻，**空腹血糖永远是正常的，而我们做体检只做空腹血糖。** 但一做胰岛素释放实验，发现她在半小时、一小时、一个半小时、两小时那几个区间段的胰岛素释放，比正常人高了五六倍、七八倍，已经爆表了。

所以，如果她不去查这件事情，可能永远就是在一个治标不治本的状态，永远好不了，一直在吃药。

**Q：提炼一下，是不是说 AI 对每个人的帮助，起码来自两项能力？**

对。**第一是上下文的阅读能力**：医生读不了那么多，他就那 10 分钟、20 分钟给你看病；而你的日常、你这一年的上下文它都在记，你要跟它聊一个小时，它就听你一个小时——它的阅读窗口足够大。

**第二是它确实有很强的推理能力。** 今天的模型已经发展到这个阶段了：有这么多上下文，又有专业领域的推理能力，它就能拿到一个很好的结果。

还有一个核心是**上下文获取**，我觉得上下文获取在国内依然是不够重视的。最核心的东西是我们一直没办法解决这个问题——**数据不开放。**

但很奇怪：谷歌的 Gemini 连的是谷歌自己的服务，是官方链接，按理说应该很准，但你去用会发现它的上下文获取很糟糕，它去读你的邮件、读你的网盘，做得还不如第三方好，特别神奇。它自己的 MCP，在任何一个非它自己的产品里边都能做得很好。

### 27 上下文是一辆要维护的车，不是一套升值的房

自从我有了那个正反馈之后，我现在就有点疯狂。尤其上次杨攀又在说他把所有上下文全部弄进去了。我现在把我每天看的、读的、聊的，全部每天让它自动清洗——**疯狂地垒上下文。**

但我发现一个问题：**它拥有我的上下文太多之后，我现在有一些新的思考，即使我明确在 prompt 里面告诉它怎么做，它还是会把我拉回到以前的平均值。** 我有点困扰。

这就是一个信息茧房，**AI 的信息茧房。**

**Q：你们会定期清上下文吗？**

我现在越来越感觉，**上下文是一辆要维护的车，不是一套升值的房。**

你不能指望一个产品帮你把上下文整理好，尤其是当你的上下文越来越多的时候，你必须自己去处理那些东西。因为你再往前走，你以前做过的那些东西是你的过去。人要不停往前，而 AI 的上下文永远要跟着你一起往前走。

**Q：那你们定期清哪些上下文？**

我觉得是**管理**：让它不要读不该读的上下文，不要上来就读所有的。做好索引。**上下文不是越多越好。**

在顶层设计上就做好：什么时候你不要读，什么时候才需要，我需要你读了你再读；除非是什么时候没找着、我让你探索，那你就开始吧。

我是在丢进去的时候让它做了一步加工，不是不停地往里丢。因为不停丢的时候，你聊着聊着它会说"你还记得上一次聊天的时候你说过什么什么"——其实跟这一次不搭嘎，或者推理逻辑完全不一样，但因为过去的上下文有那一段描述，它直接摘过来，就影响了这一次推理的思维结构。

所以我会在每次进去的时候跟它说：**我们这一次基于什么背景、我们在讨论什么话题、我们双方的对话记录是这样的。** 然后它会提炼，会有一个边界和约束在。下次再调用的时候，边界不一样了、背景不同了、话题也变了，你就不能直接引用那个东西了。

这也是刚才说的顶层设计那一步。就是有这么几条原则，加上进去的时候的清洗——我现在是通过这两个环节在做。**不止它要"紧"，你也得"紧"**，肯定不是直接往里堆、不停往里丢，那肯定是不行的。

我会觉得，**"项目"这个东西是个好东西**：我们每次做一个完整项目的时候，把它单独做一个上下文的区域管理，不要让它影响到我们的其他东西；做完之后就过去了。因为人也是这样的——我做完之后就过去了，我记下了结论、记下了认知，就往前走了。如果所有东西都放在一个地方，就会导致混乱。

**所以要抽象。** 项目的信息在项目里，那是客观信息；自己的认知在认知那边，那是你主观的迭代，包括你跟别人聊天得到的东西，也会再抽象、再抽出来。一层一层地抽。

这里还有一点，是**上下文和 agent 之间的关系**。你会发现，当你在一个 agent 中不停沉淀积累上下文的时候，这时候再来一个新 agent，你去试用，因为它没有那个上下文，你就很不适应——你只是在看功能，而不是带着上下文的那种理解。所以是 **agent 太多，上下文不够用了。**

这就是我为什么坚持迭代我自己的 agent 的原因——你的上下文都在里边。我可以用任何 agent：比如这次我觉得这个 agent 好，我就把它加到我自己的 agent 里面。**六经注我。**

### 28 而另一半人，根本没有上下文

这个也是分化的。**我们这边是上下文过多了，大部分人是根本没有上下文。**

他们根本不知道什么叫上下文，也不知道上下文在哪儿，也没有耐心跟人家去聊那种东西，都没有办法进去。

**你问他上下文在哪儿？微信啊。这是个很大的 gap。**

**Q：所以你们现在什么上下文都垒吗？包括平常聊的？**

日常的都垒。人际关系和一些情感上的我不会垒，因为那些东西都在微信里，我没法弄。关于项目和工作的基本上都会弄，认知的、包括跟人聊的也会。

所以说飞书是个好东西。飞书那个录音功能跟飞书本身结合以后——很多时候线上开会，当着别人面按录音这个东西还是有反感的，我还是有心理负担，我不会按；但线上就无所谓，他可能也猜你在录，你可能也猜他在录，因为大家都会开会嘛。无所谓，我直接把那个东西拿下来，他都看不到我，我直接一开，录完之后直接转，然后我让它从飞书再沉淀下来、拉下来，再做一次转录和总结。

你会发现——我写 skill 那篇文章不是写了一万多字吗？**那个我没有改一个字。** 全是那段时间一直在跟所有人聊 skill，聊完就成那样了。

我是刻意会放很多这种东西的：比如我读的书的笔记、我读的文章。有些东西——我觉得太多不好，不重要的东西给它反而是一种负担。**要精选，什么都要精选。** 长文很重要，长文和那些深度内容。

我现在是把我能获取的上下文全部暴力地给到我的 AI。然后我有一个很明确的**取景框：我想要变成什么样的人？**

比如在管理团队上面，我觉得迪士尼的老板管理公司管理得很好，我就用 GigaRead（音）把他的几个方法论、核心思考提炼下来。我每天让它定期看我每天聊什么、我 focus 在什么事情上面，然后拿这个人的行为处事来做校准——**你觉得我跟他还差在哪？**

它就会明确列很多东西，比如"你跟团队的沟通有问题，你给他们的共情感不够"，会有很明确的指标。这是我现在的用法。

### 29 每个人都跟自己的 agent 形成了一个闭环

我看到的是：**每个人都跟自己的 agent 形成了一个闭环**，每个人自己转起来都很开心。千奇百怪，每个人的形态都不一样，但每个人都玩得很开心。

这里边在我看来有两层觉察：

**第一层觉察是：我们应该形成自己的闭环，不应该去抄别人的。** 不是"他这么做所以我这么做"，应该是养成自己的。

**第二层是：我们要意识到自己在一个环中，别被困住了。**

这个我感慨很深。遇到过好几起情况，公司内外都有。最离谱的一个是有人说，他在 agent 上开发了一套新的框架，这个框架可以解决模型的幻觉问题——**你想，这个结论本身就是一个很大的幻觉。**

但他和他的 agent 在互相夸对方，已经在那个闭环里了。当他去尝试跟我沟通的时候，我就只能选择戳破他，然后他会很痛苦地发现这个现实。但这不是个例，确实。

**Q：那你们现在都是怎么发现自己的信息茧房的呢？跟 AI 待得越来越久之后。**

对我来说是两个方法。

**一个是把我做的一些暴论发到网上看**，被看的人多，可能就说明这是一个茧房。

**另一个是去进入长视频、去读书，去找一些 AI 之外的信源**，然后去输入。这个很重要。千万不要尽信 AI，还是得自己消费内容。

### 30 模型价格：SOTA 越来越贵，主流越来越便宜

**Q：你们刚刚在聊模型价格的问题。未来模型的价格会越来越便宜还是越来越贵？**

这个我绝对有发言权，是真实体会。

那天我发了一个内容说 DeepSeek 涨价了，大概有 17000 的曝光，然后有个人说"你写东西好像不像一个 AI 从业者"。我心想：**AI 从业者不应该最关心价格吗？** 这个价格涨十倍，影响的是我整个生意模式。我不关心这个我关心啥呢？我昨天还挣钱，今天就亏钱，那我这个就得关门。

半年前我跟一个英伟达的朋友打赌，赌模型是变贵还是变便宜。我说最前沿的模型一定是越来越贵——显卡不够，而且越来越紧张，显卡跟不上那个速度，一定会贵。他说会便宜。我们赌 100 块钱。

结果 DeepSeek 出来之后疯狂降价，降到基本大家谁都用得起，疯狂地跑也花不了什么钱。**然后我就把 100 块钱给他了。** 没想到前天我说 DeepSeek 涨价了、涨了 12 倍，你看大家又用不起了，然后**他又把那 100 块钱还给我了。**

这个行业经历了这样一个循环之后，我觉得大家会发现：AI 模型的价格好像就这样了，再往下降也没有太大区别。特别是最近某个模型降价，降得很低，有些地方甚至已经免费了——但你知道好多中转站是不降了，中转站就是在按照官方 API 在卖，**它已经没有办法往下降了，再往下降它没有任何利润，已经超过它的服务成本了。**

所以到这个节点我觉得挺微妙的。首先我觉得主流模型已经能够满足 90% 的人的需求；但是智能的模型，比如 Fable，或者下一代的那些，**它依然会很贵。** 我觉得这个节点还是挺典型的——**开始分化了。**

**Q：回看过去几年模型发布价格的曲线，是不是可以这么看：SOTA 模型永远会推出最新最强的，SOTA 模型的价格是持平的，或者说稍微还要往上涨一些；而主流模型的价格是不断像指数下降一样的。好像是两条线？**

是的。SOTA 模型是不断往上的，当然最强的就那一个。你如果想要便宜的，你就用主流的，它的价格确实一直在下降。**其实平替是越来越多了。**

我们其实很多人是在为基准测试上五分、十分的差距，付出五十倍、一百倍的价格差距。如果你只看基准，你会觉得这个东西非常亏、非常不值；**但你用起来会发现非常值——如果你真的有用处的话。**

哪怕写文章：我用某个便宜模型写完，我说这写的啥？然后我换到 Opus 4.6 重写一遍，prompt 都没改，质量一下提升很多——而价格差 100 倍。我跟很多人说这两者是天壤之别，他还不信。这就是天壤之别。

（我只用 Claude，所以我没有发言权。）但你一直在 Claude 的世界里，你没有去看过别的——有些模型的写作真的是惨不忍睹。

### 31 harness 和模型解耦，模型厂就会陷入红皇后效应

**Q：我最近在看一个报道说，harness 跟基座模型，一个像汽车的底盘、一个像上面的引擎和所有东西。以前都觉得上面的 harness 可以随便插拔到任何大模型上面，但现在会发现所有的表现都是"这个 harness 就应该配这个底盘"，它的表现是最好的，因为它是联合训练的。那对于你们这种在上面再搭一层 harness 的 OS 层，会有影响吗？**

我觉得还好。一般是这样：比如 DeepSeek 刚出来的时候是在 Claude Code 里训的，它在 Claude Code 之外的 agent 调用里就特别差；但你看后训练之后，到 Flash 那个 0731 版本开始，基本上在各个 agent 里面都跑得很好。

**数据这个东西一定会回流的**，所以这个问题不大，它只是一个时间差。

我会觉得，大部分人其实不用追求"一定要前沿到一个月的时间差"。从业者可以，但没有必要让用户去追，很累。刚才说了，主流模型已经真的满足了 90% 的需求。给朋友推荐的话，用主流的就很够了。

回到刚才那个问题，我的感觉是：**如果 harness 和模型是解耦的**，也就是说一个搭建好的 harness，我切换模型的 API 是任意的，**那就会出现模型厂商的红皇后效应——你只有拼命奔跑，才能停在原地。**

你落后就是死。因为用户的切换是零成本的：如果你现在不好用，我秒切。昨天你还是三千万用户，今天就可能跌为零，因为你不好用了而价格又贵，我凭什么用你呢？性价比不高就秒切，因为 harness 又是可替换的。

我认为过去一年就是这种状态。那你想想，如果你是模型厂，你会做什么事情？**你会把 harness 和模型一起混合训练，让我的模型和我的 harness 配套起来最好用；如果你要切，你效果就变差。** 理论上它应该往这个方向使劲，这样才能把用户拴在这儿。

但目前我实际用下来，觉得切换起来基本没有什么痛感。

现在拴住用户靠的是另一件事：**harness 的优化会提高缓存命中率，然后用降低的价格去卖，对 API 形成价格优势。**

不过在有些模型降价的时候，缓存已经如此低廉——充 50 块钱用了半年还没用完，那就不存在这个事了。而且 DeepSeek 那个缓存有黑科技：在 Cola（音）里面 DeepSeek 缓存率 96%，特别离谱；在 DeepSeek 自己的 harness 里边，缓存经常会出现 100%。

**因为缓存 90% 和 95% 是两个重要节点**，这两者的成本差异可能差两倍——因为你没有缓存的价格是有缓存的 10 倍到 100 倍之间。所以你的缓存率只要提升 5 个基点，价格一下就下来了。

但核心问题在于：**你的缓存一定会降低，或者说有可能会降低模型输出质量。** Claude Code 之前之所以那么拉胯，原因就是它为了降成本，把模型和缓存搞得过于极端了。

### 32 harness 要做的事：给用户一个目标和一条路径

**Q：那 Cola（音）现在主打的哪些功能点，你觉得是在大模型自己 harness 迭代的这条线上呢？**

其实我觉得所有功能——凡是你用它去做一个东西、做一个项目，这些东西一定是在大模型这条线上的。

然后，刚刚你讲到你跟你的 AI 沟通的时候，你会输入一个你的图景、取景框——**这个很重要，我觉得大部分人是没有这个意识的。**

就是没有告诉 AI："我长期希望我往哪个方向走。"它就是一个无状态在里面，它没有目标。

**一旦你有一个 role model、有一个方向，这个模型能关联很多很多的东西；如果你没有方向，它也帮不上什么太多忙。** 甚至很多人都不会提问。

所以我觉得这可能是一个 harness 需要做的事情：**它需要让用户进来之后找到一个目标。**

就好像多邻国一样：你说我要学英语，我不知道怎么学，我有那么多方法论，但多邻国说"你来这玩游戏就可以，打卡就完事了"。不管怎么说，你先走起来。只不过多邻国那个没什么太多智能；如果它是一个智能的 agent，用户在这儿是真的可以学会这门语言的。

**我觉得这是一个 harness 要做的事情：给用户一个目标，给用户一条路径和方法。**

因为刚刚也说了，你只给用户模型是没有用的，那只是工具，中间有 gap。所以——FDE。

**你这个产品，所谓什么叫产品？产品就是自己带一套 FDE。这样才行。**

然后你到这一层会发现：**每个产品的细分是不一样的。** 以前大家都差不多，我和 Buddy、Cola（音）做的事情都差不多，但往后会越来越不一样。因为每个模型想做的事情、擅长的事情，跟它的 onboarding、跟它的 FDE 是关联在一起的。

所以这就涉及到**每个 OS 创造者自己的审美**：他觉得他的用户进来之后要往哪个方向去？

因为人是很多样的。就像你用模型的方法，你证明了这个实践很好，你去告诉 100 个人，能听进去的估计有十个人。每个人有 P 人、有 J 人，还是很多样的。
