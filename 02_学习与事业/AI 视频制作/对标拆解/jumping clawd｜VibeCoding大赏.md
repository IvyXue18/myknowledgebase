## 可以学的手法

1. **统一画布**：深色点阵底，录屏不铺满全屏，而是作为浮窗放在画布上，配合推拉缩放。不同来源的素材（终端、浏览器、官网、代码）因此看起来是同一个视频。
2. **倒计时做承诺**：「两分钟教会你」做成真的计时器，观众有进度感；植入段暂停计时，等于告诉观众「这段是广告，不算你的时间」，广告不招人烦。
3. **人设符号**：像素猫（作者 IP「猫学长」）、表情包贴纸、自嘲「又挖坑」。这些每期能复用，比单次的好内容更能让人记住。
4. **逐句字幕 + 关键词大字**：每句一行居中字幕；术语（content script）弹出大字加一行白话解释。
5. **先给结果再讲过程**：前 30 秒只放成品和「100% 代码」「不到 50KB」这类反常识数字，后面才教。

## 作者公开的制作工具（外部观察，2026-11-28 核对 GitHub）

作者的 GitHub 组织 vibe-motion 公开了大部分画面工具，口号是「Prompts → code → motion graphics」：

- **auto-motion**：输入一份 `transcription.srt` 字幕文件，Codex 按语义把字幕拆成镜头，逐个镜头调用 Claude Code 用 HyperFrames 写 HTML 动画、渲染成 1080×1440 无声 mp4，最后用 FFmpeg 拼成 `final.mp4`。也就是说，**先有口播和字幕，再按字幕自动生成画面**。
- **skills**：一组动效 skill。本片里的「Claude Code 打字框」（0:28 处的提示词卡片）对应 `claude-typer`，迪士尼动画法则对应 `disney-animation-rule-skill`。另有 `fisheye-motion`（截图推镜 + 黄色标注）等。
- **sound**：给画面配音效的 skill，从 Freesound 搜索下载；付费「满血版」还管背景音乐和混音（在 B 站充电动态里卖）。
- **create-vibe-motion**：Remotion 脚手架，手动 vibe coding 2D 动画用。

所以这类视频的画面来源分三种：真实录屏（终端、浏览器操作）、代码生成的动效镜头、截图和表情包贴纸。哪几段是 auto-motion 自动生成、哪几段手剪，单看这一条判断不了，需要看更多期。

## 配音是真人还是 AI

**更新（2026-11-28，看完 19 条逐字稿）**：大概率是本人录的。他在 #03 里说「录到这里我才发现……」，流程是先用剪映把录好的音频转成字幕，19 条里从没提过配音或 TTS。详见 [[浙大猫学长｜制作流程反推]]。下面是只看这一条时的推断，保留备查。

逐字稿见 [01-jumping-clawd](obsidian://open?vault=%E9%9D%A2%E9%9D%A2%E7%9A%84%E7%9F%A5%E8%AF%86%E5%BA%93&file=09_Raw%2F%E8%A7%86%E9%A2%91%2F%E6%B5%99%E5%A4%A7%E7%8C%AB%E5%AD%A6%E9%95%BF%2F01-jumping-clawd)（百炼转写）。

- 语速约 6.7 字/秒，句间停顿中位数 0.4 秒，节奏紧凑、很均匀，像先写好稿子再配音，不像边操作边讲。
- 稿子里有「哎，已经好了」「嗨，俺也一样」「但但但但我」这种口语和梗，但这些都可以写进稿子里，不能证明是真人。
- 全程垫了背景音乐，没有超过 0.4 秒的完全安静段。
- 两种都还可能：本人录音，或本人声音复刻（这期是 MiniMax 植入，画面里出现了 MiniMax Speech）。要确认，得看他有没有在别的视频或仓库里提过配音方式。

真正值得学的不是配音，而是稿子写得像人说话、有人设、有梗。配音用复刻还是自己录，差别没那么大。
