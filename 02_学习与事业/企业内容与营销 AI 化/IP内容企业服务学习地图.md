# IP 内容企业服务｜系统学习地图

从客户需求到可交付系统，把业务方法、内容工序和技术能力放在同一张地图上。

研究日期：2026-09-26。以现有 IP 内容辅助系统、杨自之团队的内容服务与雪豹需求线索为应用背景。本版扩展此前的一周计划；专题顺序与练习是结合你的项目提出的建议，不是客户已接受的范围或工期。

本轮收录 77 项去重资料：24 项生财精华/案例与航海手册、2 项通用服务设计方法、51 项官方技术文档/项目/数据服务。每项标注用途、能力、限制、国内条件和核对程度。多条文档可能属于同一工具，不代表 77 个不同软件。它是一份覆盖主要环节的第一版材料库，不是市场全部项目的穷尽清单。

资料主要基于生财 MCP 正文与章节、项目官方仓库、模型卡、许可证、厂商文档。案例收入不作市场行情；官方功能说明不作实测结论。旧教程的步骤、平台权限和型号能力，实施前要用实际账号再次验证。部分页面只读到目录/官方索引或关键章节，具体状态写在材料卡片中。

## 先建立三张图

### 图一：你提供的企业服务

客户目标与现状 → 真实任务诊断 → 优先场景与关键验证 → 范围与报价 → 系统配置/开发 → 真实用户试用 → 验收培训 → 维护和下一期。

这条线决定你卖什么、承担什么、怎么付款和验收。它贯穿项目全程，不能只放在开发前读一次。

杨自之及其团队可提供业务方法、客户理解与商务推进；你负责把需求转成技术可执行的工作包并提供实施证据；最终客户要指定资料负责人、实际使用者与验收人。以上是建议分工，具体责任仍需你们确认。

### 图二：一个 IP/账号的内容生产

定位、产品、人群与信任证据 → 原始素材与方法论 → 选题池 → 内容简报 → 文章/脚本 → 按需选择图文、真人口播、素材混剪、生成视频或数字人 → 业务审核 → 平台发布 → 数据与客户反馈 → 更新选题和规则。

这些媒介是分支，不是每个客户都必须走的串行步骤。一个专家 IP 可以以真实观点和真人口播为主；品牌团队可能更需要资料准确、模板统一和多级审核；电商素材团队可能更关心批量变体与素材对位。

### 图三：承载这条流程的技术系统

客户入口（飞书/网页/表格） → 任务与审核状态 → 工作流/代码 → 知识检索与模型/媒体工具 → 素材和成果存储 → 人工审核与交付。

贯穿全链的是客户隔离、来源与版本、费用、失败处理和恢复。入口、编排、模型、媒体处理、存储是不同职责；一个热门工具通常只解决其中几项。

## 以“能交付到什么程度”组织学习

| 学习层次 | 完成标志 | 下一步 |
|---|---|---|
| 了解 | 能说明输入、输出、人工职责与限制 | 挑一种路线做样例 |
| 做出样例 | 在自己的环境完成一次任务 | 更换资料、换一个客户测试 |
| 可重复 | 多个新样本能重复完成，记录失败与成本 | 接入真实使用者和运行环境 |
| 可交付 | 有范围、验收、失败处理、培训、费用和交接证据 | 固化模板并验证下一客户 |

以下“能力上限”指适合争取的工作范围与已知边界，不代表你已实现，也不保证所有模型都有相同表现。学习时间是专题练习预算，真实访谈、资料等待和企业上线另算。

## 12 个专题的学习说明

以下学习任务和验收门槛是针对你的项目设计的练习建议。每个专题先理解职责，再选择一条实现路线。

### 01｜评估、方案与报价

**要回答的问题：** 客户究竟买什么结果？我承担哪些工作，怎样算得清、验得了？

**基本概念：** 需求诊断、业务基线、试点、范围说明（SOW）、工作包估算、验收、变更、维护。

**流程：** 线索初筛 → 老板与使用者访谈 → 看一次真实工作 → 检查资料和环境 → 排场景优先级 → 验证最难点 → 定范围 → 报价与里程碑。

| 项目 | 内容 |
|---|---|
| 输入 | 客户目标、现有流程、真实输入和合格输出、月任务量、参与人、预算/时间约束。 |
| 输出 | 一页诊断、场景优先级、一期范围、工作包与报价、客户配合清单、验收样例。 |
| 可争取的能力 | 可以形成可执行方案和成本区间；有真实样本后逐步收敛估算。 |
| 人的职责 | 业务优先级、商业价值、责任分工、最终范围与价格由双方决策。 |
| 关键边界 | “生成文章/视频”只是方向；不得据此把所有平台、所有风格和无限修改包进去。 |
| 可标准化 | 访谈提纲、诊断表、范围模板、验收模板和报价结构可以复用。 |
| 可能定制 | 行业判断、资料整理量、流程差异、接口、部署、多人协同、支持强度。 |

可选实现方法：

- 访谈加现场/屏幕走查：让客户演示最近一次怎么完成工作。
- 不确定性高时先做有限范围诊断/验证；有清晰标准的部分按项目报价。
- 把基础模块、客户配置、定制接口、运行费、维护支持分列。

**实操任务：** 选一个当前真实场景，访谈三类角色：决策者、操盘人、实际使用者；拿一组原始输入与认可成品，写出一期报价骨架。

**验收门槛：** 另一位实施者能看懂做什么、做到什么程度、依赖谁；每个收费项有交付物，每个验收项有可核对样本。

**参考投入：** 4—6小时，先完成一版；真实访谈时间另约。

优先读：

- [AI Agent 架构师｜2026年8月](https://scys.com/course/detail/190)：关卡2岗位卡→3工序→6测试交付；关卡9需求、知识库、报价与边界。
- [万字长文拆解｜FDE 小团队如何从 0 到 1 做企业 AI 服务：获客、报价、交付与验收（附完整SOP框架）](https://scys.com/articleDetail/xq_topic/22258842558211421)：按线索筛选、现场调研、范围、报价、SOW、测试、验收、回款顺序阅读；产出一份自己的范围说明。
- [半年营收50w，分享我的FDE 产品：CEO外脑 —— 让 AI 接手专家型客户手中的高精度工作](https://scys.com/articleDetail/xq_topic/82258258248488422)：学习访谈提取专家判断、建立可更新的工作依据；适合把杨自之的方法论转为系统。

### 02｜IP 定位、产品与内容策略

**要回答的问题：** 这个账号给谁看、为什么被信任、最后承接什么业务？

**基本概念：** 服务对象、真实优势、价值主张、内容支柱、信任证据、转化路径、品牌与个人IP的差别。

**流程：** 梳理真实经历/产品 → 用户问题 → 差异化判断 → 内容栏目与形式 → 转化入口 → 小批内容验证。

| 项目 | 内容 |
|---|---|
| 输入 | IP访谈、产品资料、客户问题、真实案例、历史内容与反馈。 |
| 输出 | 定位卡、受众问题清单、内容栏目、表达风格、证据清单、转化路径。 |
| 可争取的能力 | AI可整理访谈、比较方向、提出候选定位；商业定位仍要由真实用户和业务结果验证。 |
| 人的职责 | 对本人/企业的真实性、差异化与可兑现承诺作判断。 |
| 关键边界 | 模型生成的人设不能冒充真实经历；流量大不必然带来目标客户。 |
| 可标准化 | 定位字段、访谈工序和报告版式。 |
| 可能定制 | 行业价值判断、产品卖点、受众、人物口吻及专业审核。 |

可选实现方法：

- 访谈与案例反推：先找到已有可信优势。
- 对标分析：分开看话题、结构、包装与商业承接，不能只按粉丝数选。
- 用已有杨自之方法论做规则，再用真实反例验证规则适用范围。

**实操任务：** 用已有IP报告提取一张定位卡，再给第二个客户做配置对照；列出必须重访谈的字段。

**验收门槛：** 所有经历与资历有来源；每个内容栏目对应受众问题与业务目的；能解释为什么这个IP适合讲。

**参考投入：** 4—6小时；已有定位成果直接复用。

优先读：

- [AI 赋能 IP 定位｜2025年6月](https://scys.com/docx/DJo4dXLgCoqddWx3ntRciyXGnYc)：优先读定位准备、个人优势、市场方向与差异化；形成真实身份和服务对象说明。
- [【实操分享】AI 赋能小红书运营：从账号定位到批量生产内容的全流程](https://scys.com/articleDetail/xq_topic/5125551415445144)：把定位、规划、选题、创作、互动、数据、转化拆成独立任务。
- [AI 自媒体—视频号 IP 化｜2025年9月](https://scys.com/course/detail/69)：定位与内容策略→账号/场景→口播公式→录制剪辑→发布复盘。

### 03｜资料采集、知识库与方法论

**要回答的问题：** AI需要读哪些资料，怎样用对最新事实与专家判断？

**基本概念：** 事实库、规则库、风格样本、案例库、来源与有效期、检索、切分、版本与客户隔离。

**流程：** 收集授权资料 → 转写/解析 → 标注来源与状态 → 分类整理 → 提取判断规则 → 检索测试 → 更新与失效处理。

| 项目 | 内容 |
|---|---|
| 输入 | 访谈、录音、文档、产品表、历史合格稿件、修改意见、案例证据。 |
| 输出 | 最小知识包、方法卡、来源索引、缺失资料清单、更新规则。 |
| 可争取的能力 | 能提供可查资料和任务上下文；上传文档不会自动变成专家能力。 |
| 人的职责 | 判断资料真伪、冲突、适用条件以及专家规则的有效性。 |
| 关键边界 | 来源正确不代表生成结论必然正确；过期材料、跨客户误用、口吻样本与事实混用要单独测试。 |
| 可标准化 | 资料目录、字段、解析流程、来源引用、版本和归档机制。 |
| 可能定制 | 专家规则、专业术语、产品差异、权限与更新频率。 |

可选实现方法：

- 文件夹/Markdown加检索：资料不多时先保持可读和可追溯。
- 知识库检索（RAG）：资料增多时检索相关片段，再让模型生成。
- 访谈提取隐性规则：让专家说明接受/拒绝一个方案的理由。

**实操任务：** 整理20份以内与一期直接相关的材料，做10个已知答案/明确来源的问题；加入一个缺资料、一个过期、一个冲突样例。

**验收门槛：** 能找到依据、识别资料不足，重要事实可回溯；第二客户测试不会引用第一客户资料。

**参考投入：** 5—8小时；本周只做最小知识包。

优先读：

- [半年营收50w，分享我的FDE 产品：CEO外脑 —— 让 AI 接手专家型客户手中的高精度工作](https://scys.com/articleDetail/xq_topic/82258258248488422)：学习访谈提取专家判断、建立可更新的工作依据；适合把杨自之的方法论转为系统。
- [AI 知识库搭建与应用｜2025年6月](https://scys.com/docx/IK5Td6LZYoWhPQx5mRycZc4dnWb)：先读个人、专业、企业知识库的使用方式，再选择一种整理方法。
- [Dify：知识处理管道](https://docs.dify.ai/en/cloud/use-dify/knowledge/knowledge-pipeline/knowledge-pipeline-orchestration)：学习资料源→解析→切分→知识库→测试；把客户事实、风格样本、案例、禁用规则分别管理。

### 04｜选题研究与内容规划

**要回答的问题：** 接下来写什么，凭什么值得写，素材够不够？

**基本概念：** 数据输入、需求信号、对标、去重、时效性、业务相关性、选题与标题、人工确认。

**流程：** 客户问题/数据/对标/热点 → 清洗去重 → 分类与证据 → 业务筛选 → 候选选题 → 人工确认 → 内容日历。

| 项目 | 内容 |
|---|---|
| 输入 | 定位、客户问答、产品与案例、合法可用的对标数据、历史内容表现。 |
| 输出 | 有来源、有受众、有具体问题的选题池，优先级与缺素材标记。 |
| 可争取的能力 | 可自动搜集、去重、分类、初步评分；是否值得做以及是否有独特观点需要人判断。 |
| 人的职责 | 确认选题与客户价值、时机、表达角度及内容投入。 |
| 关键边界 | 对标数据可能缺失或滞后；AI评分不是流量预测，别把热点直接等同客户需求。 |
| 可标准化 | 候选库、去重、标签、来源记录、定时处理与审核状态。 |
| 可能定制 | 来源平台、行业判断、商业权重、地域、更新频率。 |

可选实现方法：

- 专家/客户问题驱动：最贴近业务，先把真实高频问题结构化。
- 账号/关键词跟踪：用后台导出、数据服务、RSS或已验证接口获取信号。
- 热点候选：TrendRadar等用于发现变化，再经过行业和业务筛选。

**实操任务：** 建立10个候选选题；用两个IP定位分别排序，核对差异是否有合理依据。

**验收门槛：** 无伪造来源，能解释优先级；重复题、过期题和缺证据题被标出；保存人工否决理由。

**参考投入：** 5—8小时；先用已有素材测筛选，再自动采集。

优先读：

- [小红书 AI 提效工作流｜2026年3月](https://scys.com/course/detail/149)：对标采集、找选题、视频封面生成；学习数据表、视图和审核状态。
- [AI 第二大脑—内容创作系统｜2026年8月](https://scys.com/course/detail/189)：2素材→3规律→4选题→5写作→6/7复盘；10视频化。
- [垂直小号自动化（n8n 工作流）｜2025年12月](https://scys.com/course/detail/104)：选题库：账号监控日报与关键词周报；内容处理、排版和结果归档。

### 05｜文章、口播稿与内容审核

**要回答的问题：** 如何把已有方法论变成稳定产出的写作流程？

**基本概念：** 素材包、结构化简报、少样本、提示词链、检索增强、风格、版本、人工评分与回归。

**流程：** 选题确认 → 素材包 → 观点访谈/确认 → 大纲 → 初稿 → 事实与风格检查 → 人工修改 → 定稿与经验回写。

| 项目 | 内容 |
|---|---|
| 输入 | 定位卡、方法卡、合格样稿、真实素材、具体选题和输出格式。 |
| 输出 | 文章/口播稿/达人brief，附事实来源、待核查项和修改记录。 |
| 可争取的能力 | 可形成可审核初稿、平台变体和改稿辅助；事实、个人观点与专业表达仍需负责人确认。 |
| 人的职责 | 原创观点、品牌判断、专业核验、最终语气与发布许可。 |
| 关键边界 | 提示词更长不等于更好；一组调试样例不能证明换行业也能稳定工作。 |
| 可标准化 | 简报格式、生成步骤、审核清单、版本与导出。 |
| 可能定制 | 风格、方法论、行业禁用表达、产品事实、审核流程。 |

可选实现方法：

- 结构化简报加少量合格样例：适合方法论已有的第一版。
- 分步骤工作流：素材、结构、写作和检查分别处理，便于找错误。
- 检索增强与评估：资料多时只调相关信息，用固定新样本比较版本。

**实操任务：** 5个选题各做一版稿件，记录修改原因；再用5个没参与调试的新选题评估，不把测试样本继续当训练答案。

**验收门槛：** 事实可回溯、无虚构经历；指定审核人认可；记录人工修改分钟数与单份被接受稿件成本。

**参考投入：** 6—10小时；优先接上现有IP工作。

优先读：

- [AI 第二大脑—内容创作系统｜2026年8月](https://scys.com/course/detail/189)：2素材→3规律→4选题→5写作→6/7复盘；10视频化。
- [我实践出来的内容创作提示词方法论，1.1w字全盘托出｜附常用提示词](https://scys.com/articleDetail/xq_topic/22255514428121421)：对话封装、反向提示、少样本提示；把合格样稿及修改意见转成可复用规则。
- [手把手教学 - 用Claude Code 搭建属于你的自动化AI内容生产系统](https://scys.com/articleDetail/xq_topic/22255845412545541)：串起定位、对标、选题、写作、改稿与反馈；关注输入资料结构。
- [Promptfoo：测试配置与断言](https://www.promptfoo.dev/docs/configuration/guide/)：用同一组真实输入比较模型/提示词；设置结构、必含要点、禁用表达和自定义检查，再加入人工评分。

### 06｜图片生成、品牌排版与组图

**要回答的问题：** 哪些图应按模板制作，哪些图值得生成？怎样保持品牌和产品准确？

**基本概念：** 模板排版、文生图、图像编辑、参考图、蒙版、主体一致性、字体与品牌资产。

**流程：** 视觉简报 → 选择模板/生成/编辑 → 参考素材确认 → 出图 → 品牌/文字/产品检查 → 尺寸适配 → 归档。

| 项目 | 内容 |
|---|---|

### 07｜录制、转写、配音与数字人

**要回答的问题：** IP本人需要提供什么，哪些环节可以辅助，哪些可以替代？

**基本概念：** ASR转写、时间戳、说话人分段、TTS配音、音色授权、数字人、口型与表达。

**流程：** 文稿确认 → 真人录音/视频或授权配音 → 转写与校正 → 音频清理 → 数字人口型（可选） → 人工审听审看。

| 可标准化 | 转写、词表、字幕格式、音频处理与归档。 |

- 数字人/口型驱动：明确有此需求时比较云服务与本地方案。

**实操任务：** 用3分钟有术语和数字的录音，比较转写错误；TTS只测一小段确认稿，记录需手改的发音。

**验收门槛：** 关键数字、人物和专业词正确；声音清晰、口型可接受；保留人工终审和授权记录。

| 可争取的能力 | 能证明约定场景中的可用性和改进；不能用一个总分证明所有行业或未来输入都正确。 |
| 人的职责 | 专业内容与最终效果验收、问题优先级、合同内外变更判断。 |
| 关键边界 | 功能演示、试用、验收、业务增长是不同证据；维护不自动包含新增场景。 |
| 可标准化 | 测试模板、版本记录、培训提纲、故障分级、备份与回归。 |
| 可能定制 | 行业验收、质量阈值、支持时段、响应约定、扩展需求。 |

可选实现方法：

- 可自动查的项目用程序查，风格/专业判断由指定审核人评。
- 把生产中的失败加入回归集；改模型/提示词后检查旧问题是否回来。
- 验收包含一次客户独立完成任务和一次恢复演练。

**实操任务：** 让未参与开发的人使用说明完成任务；用10份新样本验收，记录失败、修改、放弃及人工接管。数量是起步练习，不是统计保证。

**验收门槛：** 客户能独立使用；交付物与范围逐项对应；版本可追溯、故障能处理、维护与新增需求边界明确。

**参考投入：** 5—8小时建立机制；真实试用周期另安排。

优先读：

- [AI Agent 架构师｜2026年8月](https://scys.com/course/detail/190)：关卡2岗位卡→3工序→6测试交付；关卡9需求、知识库、报价与边界。
- [花12万找FDE踩坑失败经验，用AI自研系统，分享真实甲方的需求变现路径——完整复盘（万字长文）](https://scys.com/articleDetail/xq_topic/55522444182255514)：从甲方失败复盘反推需求翻译、可运行流程、变更和真实使用者验收。
- [Promptfoo：测试配置与断言](https://www.promptfoo.dev/docs/configuration/guide/)：用同一组真实输入比较模型/提示词；设置结构、必含要点、禁用表达和自定义检查，再加入人工评分。
- [Langfuse：生产记录、数据集与实验](https://langfuse.com/docs/evaluation/experiments/datasets)：把真实失败任务加入固定测试集；关联输入、模型版本、提示词、人工评分、成本和延迟。
- [n8n：完整备份与恢复](https://docs.n8n.io/deploy/host-n8n/keep-n8n-running/backup-and-restore)：理解工作流导出与完整实例备份的区别；客户交接时验证凭证、数据库、素材和运行配置能恢复。

## 一期架构：标准模块、客户配置、定制开发

| 层 | 可以沉淀什么 | 对报价的影响 |
|---|---|---|
| 通用模块 | 任务入口、来源记录、生成和审核、版本、保存、费用、失败处理 | 复用已有能力，但仍计算配置、验证、部署和支持 |
| 客户配置 | 定位、产品资料、方法论、口吻、品牌模板、审核规则 | 形成独立的访谈、整理与配置工作包 |
| 定制开发 | 新流程、特殊接口、复杂权限、独特视频规格、特殊部署 | 分别验证、估算、约定验收 |

不要预设“80%可复用”。先用两个客户样例运行同一模块，再记录哪些只改配置、哪些必须改代码或重新梳理方法。

### 客户说“生成文章”时，具体要拆什么

| 原话 | 可交付的拆法 | 影响工作量的问题 |
|---|---|---|
| 我们已有方法论，帮我生成文章 | 资料/规则整理 → 简报 → 素材核对 → 大纲 → 初稿 → 审核改稿 → 定稿 | 方法是否明确？多少风格/平台？谁判断合格？每月量多少？ |
| 生成图片 | 模板填充、局部编辑或新画面生成，各自明确 | 需不需要精确文字/产品？多少尺寸/模板？几轮人工修图？ |
| 生成视频 | 脚本与分镜 → 资产 → 镜头 → 筛选重做 → 剪辑 → 终审 | 新生成、真人、数字人还是混剪？时长？产品一致性？谁审片？ |
| 自动剪辑 | 转写 → 选段 → 对位 → 粗剪 → 字幕/包装 → 精修 → 导出 | 交草稿还是成片？素材怎样提供？是否需要多机位/叙事/版本兼容？ |

## 报价：从流程到工作包

先读 [AI Agent 架构师关卡 9](https://scys.com/course/detail/190) 和 [hedy 的完整交付复盘](https://scys.com/articleDetail/xq_topic/22258842558211421)，再用下面的结构做自己的估算。报价方式是本计划的建议，不是对任何帖子价格的直接套用。

1. 写清一个客户任务的起点、终点、使用者、月任务量和当前人工基线。
2. 把现有成果与新增工作分开；把资料不明、效果未测的部分列为待验证项。
3. 每个工作包分别估正常和保守投入，标出最影响估算的假设。
4. 自己的时间、外援、项目专用工具、部署、测试、培训和协调都要进入成本。通用学习属于经营投入；本项目特有的验证和集成按双方约定计入。
5. 给出范围明确的版本：先诊断/验证、一期完整交付、后续支持或扩展。不能用“维护”包住无限新增功能。
6. 对照客户价值与替代方案判断价格是否成立，必要时调整范围，再确认里程碑、付款和变更处理。

| 工作包 | 可见交付物 | 内部估算时问什么 |
|---|---|---|
| 诊断与流程设计 | 当前/目标流程、一期范围、依赖清单 | 几类使用者、几轮访谈、几个关键未知？ |
| 资料和方法论整理 | 最小知识包、规则卡、来源索引 | 材料质量、数据量、专家判断提取难度？ |
| 选题与文章 | 可运行流程、格式、规则与样例 | 几个平台、几种稿型、几个客户配置？ |
| 图像与视频 | 模板、素材处理或生成流程 | 规格、可编辑性、重做概率、人工审片强度？ |
| 连接与部署 | 客户入口、账号配置、运行实例 | 几个接口、权限、网络、并发、运行地点？ |
| 测试与验收 | 固定样本、新样本、失败与成本报告 | 由谁评、哪些自动查、几轮纠错？ |
| 培训与交接 | 说明、演练、源码/工作流与账号清单 | 谁接手、多少次培训、如何恢复？ |
| 运行与维护 | 资源预算、支持范围、响应安排 | 哪些费用按量、谁付款、什么算新增？ |

内部核算可以用：完整交付成本 = 自己的项目投入 + 外援 + 项目专用资源 + 有依据的返工/不确定性预留。若另设目标项目毛利率，未税报价底线可用“成本 ÷（1−目标毛利率）”辅助检查；这里的率由你决定，不是市场标准。计税、资源是否含在项目价内等口径要统一，避免重复计算。

生财手册中有小型 Skill、单流程应用、咨询培训等经验报价；用途是帮助认识不同产品形态，不能凭功能名字直接给你的项目定价。你此前的报价和已承诺范围要单独核对，新研究不自动修改已有约定。

## 国内交付怎么选路线

| 路线 | 适合什么情况 | 应验证什么 |
|---|---|---|
| 客户已有飞书 + 国内云工作流/模型 | 先验证业务、配置优先 | 客户账号与权限、数据流向、费用、人工审核、任务保存 |
| 客户独立国内云应用 + 国内模型 API | 有稳定使用、集成或部署控制需要 | 备份恢复、凭证、队列、存储、版本、客户隔离与支持 |
| 内网应用 + 本地模型 | 已确认资料不能送外部推理 | GPU/内存、模型下载与许可、质量下降或能力缺口、完整离线依赖、长期运维 |

优先候选是第一或第二条，最终由实际资料要求和样本测试决定。国内可访问、应用自托管、模型本地运行、完全离线是四件不同的事。[百炼地域说明](https://help.aliyun.cn/zh/model-studio/regions)可帮助区分接入、存储与推理范围。

工具学习采用“按问题选一个”的方式：

- 文字工作流：Dify 或扣子先选一条；现有代码已合适时继续复用。
- 跨系统连接：出现多个触发源、定时处理和API搬运时再学 n8n。
- 复杂分支/中断恢复：需要代码控制的定制项目再学 LangGraph。
- 知识库：先整理事实、规则与样例；复杂解析成为瓶颈时再比较 RAGFlow。
- 品牌图文：模板排版与生成画面分开，Satori/HTML 模板加一个国内图片 API。
- 视频：先生成可审核镜头，再进入剪辑；音频、视频、图片共用任务记录、存储和费用台账。
- 媒体成本：比较每份被接受成果的总成本，包含失败、重做与人工修正。

具体平台许可直接查看材料库中的官方链接。Dify、n8n、Remotion 等不能仅凭“能看到源码”就认为所有客户托管或商业嵌入都适用同一种免费许可。模型代码、权重、字体、音乐、人物素材分别看实际使用版本；这会影响路线选择与报价。

## 代表性自动剪辑路线

| 客户要什么 | 优先研究路线 | 交付边界 |
|---|---|---|
| 专家口播/访谈提效 | FunClip/Auto-Editor → 字幕 → 可编辑工程 → 人工精修 | 按文本切片与去停顿不能替代叙事判断 |
| 统一品牌模板/解释视频 | HyperFrames 或 Remotion → 参数化模板 → 渲染与审片 | 适合固定结构与批量变体，创意和品牌审美要预先设计 |
| 产品素材混剪 | MoneyPrinterTurbo 学习串联 → 客户素材与正式服务 → 审片 | 先测素材匹配和版权来源，再考虑批量 |

本轮特别核对的限制：pyJianYingDraft 的草稿生成与自动导出不同，自动导出受操作系统和剪映版本影响；OpenCut 主库在重写，旧 Classic 已归档，规划中的接口不能写入交付承诺。详细证据在各自材料卡片中。

## 八个学习阶段：按验收推进

每个阶段参考 6—10 小时的专题学习与小样实验，可按已有能力合并或跳过。生产实施、客户等待和真实效果观察不包含在该预算中。建议按 6—8 周组织；第一周就用现有 IP 项目验证，不必等所有专题学完。

| 阶段 | 重点专题 | 必须留下的成果 | 进入下一阶段的条件 |
|---|---|---|---|
| 1 商业与范围 | 01、02，全图浏览 | 一页服务架构、客户范围、报价骨架 | 能解释每个收费项和完成标准 |
| 2 资料与选题 | 03、04 | 最小知识包、10个有来源选题 | 选题符合客户定位，缺资料可识别 |
| 3 稿件与评估 | 05、12；11做最小接入 | 选题到审核稿链路、新样本评估 | 能记录人工修改与成本，客户能看懂输出 |
| 4 图片与声音 | 06、07 | 品牌图模板、图片对照、转写/配音样例 | 错字、产品、音频问题被检查和纠正 |
| 5 镜头生成 | 08 | 分镜、两条候选路线对比、费用与废片记录 | 能区分可用镜头与不值得自动化的部分 |
| 6 剪辑成片 | 09 | 一条可编辑/可重做样片及审片记录 | 明确人工精修与自动步骤、版本兼容 |
| 7 运行与反馈 | 10、11 | 客户入口、任务状态、发布台账和复盘 | 失败可追踪，结果能归档，客户网络能用 |
| 8 验收与复用 | 12，回到01 | 试用报告、培训交接、标准/配置/定制目录 | 客户独立使用；第二客户样本可验证复用 |

每专题的完整材料都保留在库中，但阅读时先看“先读”与一个实现方案。只有样本暴露了新问题，再打开备选路线；泛读可以并行，正式选型要有比较记录。

保留此前一周安排的主线，把它当成整张地图的第一轮侦察，不当作七天完成全部生产系统的承诺。

## 用三张记录卡推进

### 模块定义卡

- 业务任务与使用者：
- 原来怎么做、频次/耗时/错误成本：
- 输入、来源、可使用范围：
- 输出、格式、人工确认人：
- 标准可复用部分 / 客户配置 / 定制部分：
- 一期包括、不包括、前置条件：
- 候选方案及选择理由：
- 验收样本、指标与判断人：
- 建设成本、运行费用、维护边界：

### 技术对比实验卡

- 同一输入样本与预期成果：
- 工具/模型/工作流的具体版本：
- 成功与失败次数、问题类型：
- 总等待时间、人工修正时间：
- 全部调用/渲染费用、每份被接受成果成本：
- 新样本是否仍有效、是否可以编辑和重做：
- 当前结论：可用 / 需人工辅助 / 待验证 / 不适合本期：

### 验收与交接卡

- 范围逐项对照与证据：
- 新样本及边界/失败样例：
- 客户独立完成一次任务：
- 账号、凭证、数据、源码/工作流、版本归属：
- 重启、备份恢复、模型不可用时的处理：
- 费用入口、预算与支持安排：
- 已知限制、未完成项及后续变更：

你最终要沉淀的，是每个模块一张定义卡、一份比较记录、一组验收样本和对应报价项。这样新客户出现时，可以判断需要配置、组合还是定制，并据此解释投入。
